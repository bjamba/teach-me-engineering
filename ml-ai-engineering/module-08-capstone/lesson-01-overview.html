Module 8 · Overview·~5 min read·The finish line

Capstone & Portfolio

Three end-to-end projects you ship publicly. When you're done, "Can I work as an ML/AI engineer?" stops being a question — the artifacts answer it.

Capstones unlock after Module 7. This is where the whole curriculum converges.

The goal of this module

Everything so far has been building capability. This module proves it. By the end, you'll have three working systems — hosted, documented, version-controlled — that collectively demonstrate the full ML/AI engineering job.

Each one should be something you'd be proud to link on a resume or drop into a GitHub profile. Small enough to actually finish, real enough to matter.

The three capstones

Capstone 1 — Tabular: End-to-End Predictive Service

Pick a domain you care about (personal finance, sports, real estate, your own work data). Build a predictive model and ship it as an API that anyone can hit. Includes feature pipeline, training job, REST endpoint, monitoring dashboard, and written explanation of tradeoffs.

scikit-learn · XGBoost · FastAPI · AWS Lambda · MLflow · GitHub Actions

Capstone 2 — LLM Application: Domain RAG System

A retrieval-augmented AI application over documents you actually use — work docs, technical specs, a book collection, anything. Embeddings pipeline, vector store, RAG chain, eval harness, guardrails, cost tracking. Bonus: an agent that uses tools.

sentence-transformers · Chroma/FAISS · FastAPI · an LLM API · eval harness

Capstone 3 — Fine-Tuning: Open Model on Your Data

Take a small open model (Llama 3.1 8B or similar) and fine-tune it (LoRA) on a domain-specific task. Document what you tried, what didn't work, and what the before/after looks like. Serve the tuned model behind an API. This is the project that shows you understand training, not just API calls.

Hugging Face · PEFT/LoRA · Colab GPU · Transformers · evals

What "shipped" means here

  1. Public repo with a real README explaining the problem, approach, and results.
  2. Live endpoint that a stranger can hit (or, for the fine-tune, weights published on Hugging Face).
  3. Eval results in the repo with honest numbers, including failure modes.
  4. Architecture diagram and a clear "how I'd harden this for real production" section.
  5. Cost breakdown. How much did it cost to train, host, run? Total should stay small.
The portfolio effect

Hiring managers don't read long resumes closely. They do read three clean, well-documented projects that map to the actual job. These three capstones — tabular, LLM app, fine-tune — together cover the core surface area of modern ML/AI engineering hiring.

When you're done

Come back to this dashboard. You'll have walked from "math is rusty and I've never built a model" to three production-shaped systems in your GitHub. That's the proof. Go apply for the jobs.
