Modern AI: Transformers & LLMs

Attention, transformers, fine-tuning, retrieval, agents. This is where "ML engineer" becomes "AI engineer" — and the part of the market that's hiring hardest.

Lessons unlock after Module 5. This page is your preview.

Why this matters

Most of what makes a 2026 AI engineer productive isn't writing transformers from scratch — it's knowing the shape of them, knowing when to fine-tune vs. prompt vs. retrieve, knowing how to wire an LLM into a production system with eval and safety nets. That's the exact skill set this module builds.

What you'll learn

Lesson 1 — Attention Is All You Need (Really)

The self-attention mechanism, derived patiently. Queries, keys, values — what they actually represent geometrically.

Lesson 2 — The Transformer Block

Multi-head attention, positional encodings, residual streams, layer norm. You'll build a minimal GPT in ~150 lines of PyTorch.

Lesson 3 — Pretraining, Fine-Tuning, and Instruction Tuning

What "a foundation model" actually is. Supervised fine-tuning (SFT), LoRA/PEFT, RLHF and DPO at a conceptual level.

Lesson 4 — Prompt Engineering That Scales

Prompts as programs. System prompts, few-shot, chain-of-thought, structured outputs, tool-use schemas. The difference between a prompt that works once and one that holds up in production.

Lesson 5 — Retrieval-Augmented Generation (RAG)

Embeddings, vector databases, chunking strategies, reranking. The pattern that makes LLMs actually useful with your own data.

Lesson 6 — Agents & Tool Use

Tool-calling loops, planning, multi-agent patterns, eval harnesses. How to build something that does work, not just answers questions.

Lesson 7 — LLM Evaluation

Why traditional metrics don't work. Golden datasets, LLM-as-judge, regression testing for prompts, red-teaming basics.

Exercises you'll build

  • A minimal GPT-style transformer trained on Shakespeare — small enough to run on a laptop, big enough to produce recognizable output.
  • A RAG system over your own document collection with sentence-transformers + a local vector store.
  • An agent that can plan, call tools (search, calculator, code interpreter), and answer multi-step questions — with an eval suite that scores each version against the last.
  • A LoRA fine-tune of a small open model on a specific domain.
Free-tier friendly

We'll use small open models (Llama/Mistral variants, ~1–7B parameters) so everything runs on free Colab or a modest local machine. Where an API call makes sense, we'll use the cheapest option available and cap spend explicitly.
