MLOps & Production Deployment

From notebook to production. Most of MLOps is ordinary engineering — roughly 70% overlap with backend/data-infra work, just with an ML-shaped vocabulary bolted on top.

Lessons unlock after Module 6. This page is your preview.

Why this matters

A model in a notebook is a hypothesis. A model in production is a product. The gap between the two is where most ML initiatives die — and it's exactly where engineering discipline outperforms research ability. This is where production ML is actually won.

Focus throughout: low-cost, easy-to-deploy, AWS-friendly. We'll use free tiers aggressively and lean on tools that don't require a platform team to operate.

What you'll learn

Lesson 1 — Experiment Tracking & Model Registry

MLflow locally and in S3. Logging runs, comparing experiments, versioning artifacts. Why "I got 0.89 on my laptop last week" isn't good enough.

Lesson 2 — Packaging a Model for Serving

FastAPI wrappers, request/response schemas with Pydantic, Dockerizing inference. Batch vs. real-time serving and when each fits.

Lesson 3 — Deploying on AWS (The Cheap Way)

Lambda for low-traffic inference, ECS Fargate for medium, SageMaker when justified. IaC with a simple Terraform or AWS CDK setup. You'll have a model serving real HTTP traffic by the end.

Lesson 4 — CI/CD for ML

GitHub Actions pipelines for training, testing, and deploying models. Gating deploys on eval metrics. How ML pipelines differ from software CI/CD — and how they're the same.

Lesson 5 — Monitoring, Drift, and Retraining

Input drift, prediction drift, delayed outcome tracking. Shadow deployments, canary releases, rollback strategies. How to know when to retrain without being woken up at 3am.

Lesson 6 — Feature Stores & Data Contracts

Train/serve skew is the #1 cause of production model failures. A lightweight feature-store pattern (Feast or DIY on S3/DynamoDB). Data contracts between upstream pipelines and ML consumers.

Lesson 7 — LLM-Specific Ops

Evals as regression tests, prompt versioning, cost monitoring, guardrails, fallback chains. What's different when the model is a black-box API you don't control.

Exercises you'll build

  • A full CI/CD pipeline: commit → train → eval → deploy to Lambda, with a teardown script.
  • A drift monitoring dashboard for a deployed model using Grafana or a simple Streamlit app.
  • An LLM eval harness that runs on every prompt change, with cost and latency budgets enforced.
Cost discipline

Every AWS exercise comes with a teardown script and a cost estimate. You should never wake up to a surprise bill. The goal is to learn the patterns for under $5 total across the whole module.
