Feature Engineering & Unsupervised Learning

Data beats algorithms. Features beat data. This module is about the craft that separates ML tutorials from ML systems that actually work.

Full lessons unlock after you complete Module 3. This page is your preview.

Why this matters

In Kaggle competitions and real production systems alike, the gap between a 5% model and a 95% model is almost never the algorithm. It's the features. The engineer who knows how to shape raw columns into signal — and how to extract structure from unlabeled data — wins most of the time.

This module is also where your SQL/dbt background becomes a superpower. Most feature engineering is disciplined data transformation. You already know how to do this; you just need the ML-specific vocabulary.

What you'll learn

Lesson 1 — Numeric Feature Engineering

Scaling, normalization, binning, log transforms, interaction features, polynomial expansion. When each is helpful, when each makes things worse.

Lesson 2 — Categorical & Text Features

One-hot, target/frequency encoding, embeddings, TF-IDF, hashing tricks. How to handle high-cardinality categories without blowing up the pipeline.

Lesson 3 — Time Series & Windowed Features

Lags, rolling windows, time-since-last-event, cyclical encoding (hour-of-day, day-of-week). Avoiding lookahead leakage.

Lesson 4 — Unsupervised Learning

Clustering (k-means, DBSCAN, hierarchical), dimensionality reduction (PCA, UMAP, t-SNE), anomaly detection. Both as standalone tools and as feature generators.

Exercises you'll build

  • A feature pipeline for the same housing dataset you used in Module 3 — measure how much features alone move the score.
  • User segmentation on real web-log data with k-means and UMAP visualization.
  • A feature store mini-project: cached, versioned features served to the model.
Your edge here

Coming from dbt, you'll recognize feature engineering as "staging + marts for ML." The disciplines of idempotence, testing, and lineage all carry over directly. We'll lean into that.
