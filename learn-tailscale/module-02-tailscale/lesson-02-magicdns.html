MagicDNS

The feature that makes a tailnet feel like one network. Stop typing IPs. Use names.

1What it does

When you enable MagicDNS in your tailnet (one toggle in the admin console — covered in M3), every device gets two names:

  • The short name: laptop, home-server, kid-phone. Just the device's hostname.
  • The full name: laptop.your-tailnet.ts.net. Always unique, always works.

From any device on your tailnet, both names resolve to the device's tailnet IP. You can ssh laptop, curl http://home-server, browse to http://jellyfin:8096 — all without ever typing an IP.

2How it works (briefly)

Tailscale's client on each device intercepts DNS queries. If the query is for a tailnet device name, Tailscale answers it directly. If the query is for anything else (google.com), Tailscale forwards it to your normal DNS resolver and you get the regular answer.

This means MagicDNS doesn't break anything — public DNS works as before; tailnet names just also work.

The aha: there's no DNS server you have to run, no zone file to manage. The Tailscale client is the resolver, and the source of truth is the tailnet itself.

3Why this matters more than it sounds

For a tailnet of 5 devices, MagicDNS is convenient. For 30, it's transformative. Without it, every project would say "find the IP of your home-server (probably 100.64.x.y) and configure that here." With it: "use home-server." The instructions stay portable — they work for any reader.

Every project in the rest of this course assumes MagicDNS is on. We'll turn it on as part of M3 setup.

4One thing to know

Names should be lowercase, no spaces. Tailscale will normalize a hostname like "Your Laptop" to your-laptop. You can rename devices in the admin console if the auto-derived name is awkward. You'll do this in M3.
