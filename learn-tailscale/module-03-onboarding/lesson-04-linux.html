Linux

One install command per distro. Then tailscale up. Whole thing is two terminal commands plus a browser auth.

1Install

# One-line install (Tailscale's official script):
curl -fsSL https://tailscale.com/install.sh | sh

If you'd rather not pipe-to-shell, the manual version is documented at tailscale.com/download/linux/ubuntu — it's a few apt commands adding their package repo. Either is fine.

sudo dnf config-manager --add-repo https://pkgs.tailscale.com/stable/fedora/tailscale.repo
sudo dnf install tailscale
sudo systemctl enable --now tailscaled
sudo pacman -S tailscale
sudo systemctl enable --now tailscaled

Tailscale supports almost every distro. See tailscale.com/download/linux for your specific one — the install method varies but the steps after are identical.

2Bring it up

sudo tailscale up

The terminal prints a URL. Copy it, paste into a browser (on any device — doesn't have to be this one). Authorize. The terminal returns a prompt and you're connected.

Tip: if you're SSH'd into a headless box and don't have a browser handy, copy the URL into a browser on your laptop. The auth happens on Tailscale's site, not the device.

3Verify

tailscale status      # list of devices
tailscale ip -4       # this device's tailnet IP

The status output shows every device in your tailnet, with their tailnet IPs and connection state.

4Useful flags

Some tailscale up flags you'll see referenced later:

  • --ssh — enable Tailscale SSH (M4 covers this)
  • --advertise-routes=192.168.1.0/24 — advertise this device as a subnet router (M4)
  • --advertise-exit-node — make this device offer to be an exit node (M4)
  • --accept-routes — accept advertised subnet routes from other devices
  • --auth-key=tskey-... — non-interactive auth using a pre-shared key (M3L6)

For now sudo tailscale up on its own is enough. We'll layer flags in later modules.

5What's next

If this is your home server, you're about to use it as an SSH target (L7) and as a host for projects (M4 onwards).

🧠Knowledge check

Three quick questions

Q1.You ran sudo tailscale up on a headless server. The terminal prints a URL. What now?
Right. The auth flow is decoupled from the device — you authorize on Tailscale's site from any browser.
Headless servers don't have browsers. Copy the URL.
Auth happens in the browser, via your identity provider.
Will time out. You need to authorize via the URL.
Q2.What does --ssh do (when you'll see it)?
Right. Tailscale SSH is a feature where Tailscale handles authentication, so you can ssh user@machine over your tailnet without managing SSH keys yourself. M4 covers this.
Doesn't install OpenSSH. Different mechanism.
Not the behavior. Tailscale handles SSH auth itself.
Doesn't affect traditional SSH; they coexist.
Q3.You ran the install on Ubuntu but tailscale command isn't found. Most likely cause?
Right. Most "command not found" cases on Linux are install-failed-quietly. Re-run the install or check the script's output.
Ubuntu is one of the most-supported.
DNS isn't related to whether the binary exists.
Kernel version is rarely the issue for Tailscale.
