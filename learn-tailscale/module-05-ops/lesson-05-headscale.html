The Headscale escape hatch

Open-source, self-hosted Tailscale coordinator. Doesn't replace your Tailscale clients — replaces only the part Tailscale Inc. runs.

1What Headscale is

Headscale is an independent reimplementation of Tailscale's coordination server. It speaks the same protocol the Tailscale clients expect. You run it on a $5/mo VPS or a home Pi; your clients (the same Tailscale Mac/iOS/Windows/Linux apps) connect to your Headscale instance instead of login.tailscale.com.

The data plane (WireGuard, peer-to-peer connections) is unchanged.

2What you get

  • No reliance on Tailscale Inc. for tailnet management.
  • No device limit (free Tailscale caps at 100 — Headscale has no cap).
  • Data sovereignty — coordination metadata lives on your server.
  • Open source — you can read the code, fork it, audit it.

3What you give up

  • The admin web UI. Headscale is CLI-driven (third-party web UIs exist, with varying maturity).
  • Some features lag. Tailscale Inc. ships features in their coordinator first; Headscale catches up over time. Funnel, for instance, requires Tailscale's edge infrastructure and isn't supported by Headscale.
  • You're now responsible for uptime. If your Headscale instance goes down, new device joins fail (existing connections still work, like the regular outage scenario).
  • You manage TLS for the coordinator endpoint, plus DERP relays if you want self-hosted ones.

4Should you switch?

Probably not, if you have ~10 devices, use Tailscale free tier, are happy with the admin console, and value features over self-hosting.

Probably yes, if you're running a self-hosting community, have data sovereignty requirements (research, healthcare, compliance), or have grown past the free tier and don't want to pay.

For this course's audience — someone learning to network their devices — Tailscale's free tier is fine. Headscale is the escape hatch when you need it.

5Migration path

Going from Tailscale to Headscale isn't seamless — you'll re-enroll devices against the new coordinator. The ACL syntax is similar (Headscale supports a HuJSON-ish format), but you'll port your policy over.

Plan: bring up Headscale, test with one device, migrate gradually, decommission your Tailscale-coordinated tailnet last. Project in the Gallery walks the full setup.
