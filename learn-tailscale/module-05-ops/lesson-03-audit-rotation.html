Audit logs & key rotation

Two operational habits that cost almost nothing and save a lot when something feels off.

1Where logs live

Admin console → Logs. Tailscale records significant events:

  • Devices added or removed
  • ACL policy edits (with diffs)
  • Auth key creations
  • Sign-ins (sometimes — on paid tiers there's more)

Skim weekly for personal use, or after anything weird ("did I add that machine? did someone else?").

2What to rotate, and how often

Auth keys: rotate quarterly, or after any suspected leak. Generate a new key, update wherever the old one was used, then revoke the old key in admin console → Settings → Auth keys.

Node keys: handled by key expiry (180 days default). Don't disable expiry on devices that aren't physically secured.

OAuth client credentials: rotate yearly. Same drill — generate new, deploy, revoke old.

3What to do when a device is lost

  1. Admin console → Machines → find the device → click → Remove.
  2. It's revoked immediately. Even if the laptop comes back online, it can't rejoin without re-auth.
  3. Skim the Logs page for anything unexpected from that device's history.

4What to do when a person leaves

Admin console → Users → click their name → Suspend or Delete. Their devices come along with the user — suspension/deletion takes them all out at once.

Tag-owned devices are unaffected by user deletion (the whole point of tags is exactly this).

5The 5-minute weekly review

For an hour-or-two-a-week home setup, this is enough:

  • Open Machines. Anything you don't recognize? (Probably not, but glance.)
  • Open Logs. Any policy edits you didn't make?
  • If you have auth keys, check expiration dates. Rotate ones that'll expire soon.
