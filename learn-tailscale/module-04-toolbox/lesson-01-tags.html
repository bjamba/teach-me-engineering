Tags

A way to label devices that's separate from "who owns them." Tags are the foundation of clean ACLs.

1The problem tags solve

By default, every device is owned by the user who added it. ACLs reference users:

"src": ["you@example.com"], "dst": ["*:*"]

That works for a couple of personal laptops. It breaks down for servers, IoT devices, containers — devices that don't really belong to a person. The user "owning" them is a coincidence of who installed Tailscale.

Tags decouple the device from its owner. A device tagged tag:server is the server, period. ACLs reference the tag, not the human. When you replace the box, the tag stays consistent.

2How tags work

  1. You declare which tags exist and who owns them in the tagOwners section of your ACL policy.
  2. You apply tags to a device when registering it — either via --advertise-tags on tailscale up, or in the admin console.
  3. ACLs reference tags directly: "src": ["tag:server"], "dst": ["tag:server:*"].
// In your ACL policy:
{
  "tagOwners": {
    "tag:server": ["group:family"],
    "tag:iot":    ["group:family"],
    "tag:ai":     ["group:family"]
  }
}

"tag:server is owned by group:family" means anyone in group:family can apply this tag to a device they're registering.

3Apply a tag at registration

sudo tailscale up --advertise-tags=tag:server

You'll need to re-authenticate. After this, the device shows up in the admin console as tagged. It's no longer "owned by you@example.com" — it's owned by tag:server.

Note: a device can have multiple tags (e.g. --advertise-tags=tag:server,tag:ai) but the tags must be declared in tagOwners first.

4Common tag conventions

  • tag:server — anything that hosts services (web, AI, media)
  • tag:iot — smart-home devices, sensors, anything you don't want to trust laterally
  • tag:ai — your local AI rig (Ollama)
  • tag:media — Jellyfin / Plex hosts
  • tag:dev — dev machines you might give CI access to
  • tag:guest — shared devices with limited access

Define the tags that match how you think about your network. M5 covers patterns for production-style setups.

🧠Knowledge check

Three quick questions

Q1.Why use a tag instead of a user for a server?
Right. A user-owned device's identity changes when ownership changes. A tagged device's identity is the role itself.
Speed isn't the issue.
Tailscale works without tags; tags improve ACL design.
Tags are free.
Q2.How do you apply a tag to a device?
Right. Two-step: declare the tag in policy first, then advertise it on the device.
No env var.
The policy is configured in the admin console, not a per-device config file.
Self-service.
Q3.What does tagOwners control?
Right. tagOwners is about who can stamp a tag onto a device. Access is controlled separately by ACLs.
That's ACLs. tagOwners is about who can apply the tag.
No pricing concept.
Cosmetic, but no.
