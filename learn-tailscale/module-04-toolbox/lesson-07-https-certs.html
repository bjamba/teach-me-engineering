HTTPS certs & MagicDNS

How Tailscale gets a real Let's Encrypt cert for your-device.tail-abc.ts.net, and how to use one in your own apps.

1Where the certs come from

When you turn on MagicDNS + HTTPS in your tailnet (admin console → DNS → enable "HTTPS Certificates"), Tailscale provisions Let's Encrypt certificates for every device.tail-abc.ts.net hostname.

Tailscale Serve uses these automatically. So do Funnel-exposed services.

2Get a cert for your own app

If you're running your own web server (not via Serve) and want a Tailscale cert:

sudo tailscale cert your-device.tail-abc.ts.net

Outputs your-device.tail-abc.ts.net.crt and .key in the current directory. Configure your web server (nginx, Caddy, Traefik) to use them.

Certs auto-renew via Tailscale's automation.

3The "tailnet name" matters

Your tailnet has an auto-generated name like tail-abc123.ts.net. You can rename it (admin console → DNS → Tailnet name) to something you'll remember, like your-tailnet.ts.net. After this, devices are laptop.your-tailnet.ts.net.

Existing certs keep working with the old name; new certs use the new name. Renaming is cheap.

4Why this is unusual

Normally getting a public TLS cert means owning a domain, proving you control it, and running a renewal robot. Tailscale skips all of that — they own ts.net and provision sub-certs for tailnet devices.

The aha: internal services with valid certs used to be a sign of mature infrastructure. With Tailscale, every tinkerer gets it for free.
