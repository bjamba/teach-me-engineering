Tailscale Serve

Expose a local service to your tailnet — over HTTPS, with a valid cert, accessible by hostname. One command.

1What it does

You have a service running locally — a web app on port 3000, an API on 8080, a static site. tailscale serve publishes it to your tailnet at https://your-device.tail-abc.ts.net, complete with a real Let's Encrypt certificate.

Other people on your tailnet (and only them) can reach it. The world cannot.

2The simplest case

You're running a local dev server on port 3000. To expose it on your tailnet:

sudo tailscale serve --bg https://3000

"Serve port 3000 over HTTPS in the background." Tailscale obtains a certificate, sets up the proxy, and the service is now reachable at https://your-device-name.tail-abc.ts.net from any device on the tailnet.

To stop:

sudo tailscale serve --https=443 off

3More patterns

# Serve a different port at /api:
sudo tailscale serve --bg --set-path=/api https://3000

# Serve static files from a directory:
sudo tailscale serve --bg https /path/to/files

# Reverse-proxy to localhost:8080:
sudo tailscale serve --bg https http://localhost:8080

# Show current config:
sudo tailscale serve status

4Why this is amazing

  • No cert manager, no certbot, no DNS challenges
  • No port forwarding, no firewall edits
  • HTTPS by default — your service gets transport encryption for free
  • Only tailnet members can reach it (private by default)
  • The hostname is stable; share it with friends on your tailnet

The aha: hosting an internal tool used to be a multi-day project (cert + DNS + firewall + auth). Now it's one command.

5Try it

If you have any local web server (or just python3 -m http.server 8000 in any directory):

sudo tailscale serve --bg https http://localhost:8000

Then visit https://your-device-name.tail-abc.ts.net from your phone. Pages load. With a valid cert. Without you having configured anything.
