⭐ Core project · #1

🏠 Reach your home machine from anywhere

SSH into your home server from a coffee shop. Copy files between your laptop and home. The "aha" project — proves the network you just built actually works the way M1 promised.

⭐ Core Networking Beginner ~30 min Prereqs: M3 (onboarding)

Why this project

Two devices on a tailnet should feel like they're plugged into the same router — even if one's at home and the other's a thousand miles away. This is the simplest possible demonstration of that promise: SSH from somewhere remote into something at home.

Once this works, you have everything you need to host services and reach them from anywhere — Jellyfin, Home Assistant, a private website, whatever. This is the wedge.

Who this helps

  • You have a desktop or home server you'd like to reach from your laptop while traveling
  • You're tired of opening port-forwarding rules on your router every time you want remote access
  • You want SSH to just work over a stable hostname instead of a public IP that keeps changing

What you get

  • ssh you@home-server works from any tailnet device, regardless of location
  • scp in both directions: pull files from home, push files to home
  • No public IP, no DNS, no port forwarding, no certs to manage
  • The same setup works the same way whether you're on home wifi, hotel wifi, or cellular

Same two devices either way. The router is the same too. What changes is whether you're trying to punch through the router (left) or quietly tunnel around it (right).

Prerequisites

  • Tailscale running on at least two devices (M3 onboarding)
  • One of them is the device you want to reach (home server, beefy laptop, NAS)
  • An SSH server installed on the home device (most Linux/macOS already have one; Windows needs OpenSSH installed)

Steps

Verify both devices are on the tailnet ~2 min

From your client device (laptop, phone), check that you can see the home device:

tailscale status

You should see the home device listed with its tailnet IP. If not, revisit M3L7.

Make sure SSH is running on the home machine ~5 min

sudo apt install openssh-server  # Ubuntu/Debian
sudo systemctl enable --now ssh

# Verify it's listening:
sudo ss -tlnp | grep :22

macOS includes SSH but it's off by default. Enable in System Settings → General → Sharing → Remote Login. Or via CLI:

sudo systemsetup -setremotelogin on

Add the OpenSSH Server feature: Settings → System → Optional features → Add → OpenSSH Server. Then start it:

Start-Service sshd
Set-Service -Name sshd -StartupType Automatic

Connect by name ~1 min

From your client device:

ssh you@home-server

Replace you with your username on the home machine and home-server with whatever you named that device in the admin console.

Authenticate (password or SSH key), and you're now in a shell on your home machine.

Test it from somewhere else. Disconnect from your home wifi, tether to your phone instead, run the same command. It still works. That's the whole point of this course.

Copy files with scp ~2 min

Send a file:

scp ./report.pdf you@home-server:~/Documents/

Pull a file:

scp you@home-server:~/Pictures/photo.jpg ./

For folders, add -r: scp -r ./project you@home-server:~/.

Optional: skip password entry with SSH keys ~5 min

# On your client, generate a key if you don't have one:
ssh-keygen -t ed25519

# Copy your public key to the home machine:
ssh-copy-id you@home-server

# Now SSH in — no password prompt.
ssh you@home-server

Optional: use Tailscale SSH instead ~5 min

Tailscale offers its own SSH-handling that skips key management entirely. Tailscale authenticates you based on your tailnet identity; ACLs decide who can SSH in.

On the home machine:

sudo tailscale up --ssh

Now ssh you@home-server works without you ever having set up SSH keys. Add an ACL rule to restrict who can connect:

"ssh": [
  { "action": "accept", "src": ["you@example.com"], "dst": ["you@example.com"], "users": ["you", "root"] }
]

Verify

  • You can SSH from your client to the home machine using the device name (not an IP)
  • It works regardless of where your client is (home wifi, cellular, coffee shop)
  • You can copy a file in both directions with scp

Common issues

  • Connection refused — SSH server isn't running on the home machine. Check step 2.
  • Connection timed out — the home machine isn't reachable on the tailnet. tailscale ping home-server to debug.
  • Permission denied — username or password wrong. SSH config issue, not Tailscale.
  • Slow — you might be going through a DERP relay. Functionally fine, just expect higher latency than direct.

Where this leads

  • Private website on your tailnet — host a real service, not just SSH
  • Local AI gateway — same idea, different service
  • Tech support for your parents — extend the SSH pattern to other people's machines
