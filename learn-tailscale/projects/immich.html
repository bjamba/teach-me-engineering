📸 Immich photo library

Self-hosted Google Photos. Auto-upload from phones, ML-powered search, shared albums — all on your tailnet.

Gallery Self-Hosted Beginner Half-day Prereqs: Docker sidecar pattern

Why this project

Google Photos is convenient and reliable, but you're paying with both money and the rights to your kids' faces. Immich gives you the same UX (auto-upload, face recognition, semantic search) on your own hardware, with nothing leaving your home network. Tailscale handles the "reach it from my phone" problem that historically killed self-hosted photo libraries.

Who this helps

  • You have a multi-year photo library and don't want it living on Google's servers
  • You're paying for Google One storage and would rather invest in disks you own
  • You want the family to share albums without inviting strangers

What you get

  • Immich at https://immich.tail-abc.ts.net with a real cert
  • Mobile auto-upload from iOS/Android Immich apps
  • Local face recognition and semantic search (e.g. "beach" returns beach photos)
  • Shared albums with other tailnet users

Prerequisites

  • Linux host with substantial disk (a 5-year photo library is easily 200GB+)
  • Docker + docker-compose
  • The Docker sidecar pattern
  • HTTPS Certificates enabled in admin → DNS

Steps

Follow Immich's official docker-compose ~15 min

Use Immich's official install on your home server. It includes the server, microservices, machine-learning, postgres, and redis containers.

Wrap it with a Tailscale sidecar ~10 min

Add a sidecar service that shares network namespace with the Immich web server. The official compose file uses ports: ["2283:2283"] — replace that with the sidecar pattern from the Core project:

services:
  ts-immich:
    image: tailscale/tailscale:latest
    hostname: immich
    environment:
      - TS_AUTHKEY=${TS_AUTHKEY?required}
      - TS_EXTRA_ARGS=--advertise-tags=tag:media
      - TS_SERVE_CONFIG=/config/serve.json
    volumes:
      - ts-state:/var/lib/tailscale
      - ./serve-config.json:/config/serve.json
    cap_add: [net_admin, sys_module]

  immich-server:
    # ... from official docker-compose ...
    network_mode: service:ts-immich
    # remove the `ports:` block — sidecar handles it

Serve config proxies to http://127.0.0.1:2283.

Initial setup ~10 min

Visit https://immich.tail-abc.ts.net. Create the admin account. Pick storage paths. Wait for the initial scan if you've pointed at an existing library.

Install the mobile app ~5 min

iOS / Android: install Immich. Open, point at your tailnet URL, sign in. Enable auto-backup. Photos start uploading whenever your phone is on the tailnet.

Lock it down with ACLs ~3 min

Photos are sensitive. Restrict to group:family only:

{ "action": "accept", "src": ["group:family"], "dst": ["tag:media:443"] }

Set up backups ~15 min

Your library is now your responsibility. Back up the Postgres database AND the upload directory regularly. Restic to B2/S3 is the typical pattern. Test a restore at least once.

Verify

  • Immich web UI loads from a phone over the tailnet
  • Mobile app uploads new photos in the background
  • Face recognition runs (check the People view after a scan)
  • Off-tailnet visitors can't reach the URL

Common issues

  • ML container fails on resource-limited hosts — disable specific ML features, or run the ML container on a beefier host and point at it.
  • Mobile uploads stall — make sure background app refresh is on; check that the phone is actually on the tailnet (not just wifi).
  • Database errors — most are caused by upgrading the server image without upgrading Postgres compatibly. Read the changelog.

Caveats

  • ML processing happens locally and is slower than Google's (especially face recognition on first run)
  • Sharing with non-tailnet users requires either inviting them to your tailnet or generating a one-off public share link (Immich supports this)
  • You manage storage capacity yourself — when the disk fills, photos stop uploading

Where this leads

  • Vaultwarden — passwords for your home stack
