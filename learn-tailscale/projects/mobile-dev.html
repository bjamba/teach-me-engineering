📱 Mobile dev: phone → localhost

Test your local dev server from a real phone. No ngrok, no tunnels, no separate IP for your laptop. Tailscale gives your phone a path to your dev box's localhost.

Gallery Dev Workflow Intermediate ~30 min Prereqs: M3

Why this project

Real-device testing of a web app is fiddly. Same-wifi tricks break when your laptop and phone are on different networks. ngrok works but burns tunnel limits and gives random URLs that change. Tailscale Just Works — your laptop and phone are on a stable network with stable hostnames, regardless of where either is. OAuth callbacks and HTTPS-gated browser features (camera, PWA install) suddenly work in dev.

Who this helps

  • You're building a web app and need real-device Safari/Chrome testing
  • You're tired of ngrok's free-tier limits and random URLs
  • Your app uses OAuth or browser features that need a stable HTTPS URL even in dev

What you get

  • Your dev server reachable from your phone at http://your-laptop:5173 (or HTTPS via Serve)
  • Stable hostname that doesn't change between sessions
  • Real Let's Encrypt cert if you use Tailscale Serve (unlocks PWA install, camera, getUserMedia)
  • OAuth callbacks that actually work in dev because the redirect URI is stable

Prerequisites

  • Tailscale running on your laptop and phone (M3)
  • A dev server you're already running locally
  • HTTPS Certificates enabled in admin → DNS (only if you want HTTPS)

Steps

Confirm both devices see each other ~2 min

From either, tailscale status should list the other.

Bind your dev server to all interfaces ~3 min

By default, dev servers bind to 127.0.0.1 only — meaning only the local machine can reach them. Bind to 0.0.0.0:

  • Vite: vite --host
  • Next.js: next dev -H 0.0.0.0
  • Django: python manage.py runserver 0.0.0.0:8000
  • Flask: flask run --host=0.0.0.0
  • Most node servers: HOST=0.0.0.0 npm run dev

Reach it from your phone ~1 min

On your phone's browser, navigate to http://your-laptop:5173 (use your actual hostname/port). The page loads.

Optional: HTTPS for service workers, camera, geolocation ~5 min

Browsers gate PWA install, camera, getUserMedia to HTTPS. Tailscale Serve gives you HTTPS for free:

sudo tailscale serve --bg https http://localhost:5173

Now visit https://your-laptop.tail-abc.ts.net. Real cert, secure context, all browser features unlocked.

OAuth callbacks during dev ~5 min

Add your tailnet hostname to the OAuth app config:

# Authorized redirect URI:
https://your-laptop.tail-abc.ts.net/auth/callback

Now you can test full OAuth flows from your phone.

Verify

  • Page loads on your phone via tailnet hostname
  • HMR (hot-reload) works as you edit code
  • HTTPS variant unlocks camera/getUserMedia/etc. on the phone
  • OAuth callbacks complete from phone

Common issues

  • HMR doesn't reconnect over tailnet hostname — some frameworks need extra config (Vite's server.hmr options) to use the hostname rather than localhost.
  • Hardcoded localhost:5173 in app code — those URLs break when accessed from the phone. Use relative URLs or env-aware config.
  • Phone reaches but nothing loads — your dev server didn't actually bind to 0.0.0.0; check the start command.

Caveats

  • Don't accidentally Funnel your dev server. Debug routes are public exposure waiting to bite
  • If your laptop sleeps, the dev server dies — phone reaches a dead URL
  • Some dev frameworks have HMR over websockets that need extra config to work over hostname-based access

Where this leads

  • Funnel — when you genuinely need a public URL for a webhook test
  • Actions runner — your CI box on the same tailnet for build/deploy testing
