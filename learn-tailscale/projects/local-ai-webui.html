💬 Local AI: add a chat UI

Put Open WebUI — a polished ChatGPT-style frontend — in front of the private API you built in part 1. Reach the chat from any tailnet device. Same Tailscale Serve pattern; nothing about the engine changes.

Featured AI/ML Intermediate ~30 min Prereqs: Local AI gateway (part 1)

Why this project

Part 1 left you with a working private LLM API — great for scripts, editor tools, and other automations, but awkward for the most common use case: just chatting with the model. curl doesn't remember conversations, can't switch models mid-thread, and isn't fun to use on a phone.

Open WebUI is a self-hosted ChatGPT-style UI that speaks the OpenAI-compatible API your engine already exposes. Drop it in, put Tailscale Serve in front of it instead of (or alongside) the raw API, and you've got a private chat interface reachable from every device you own.

Who this helps

  • You completed part 1 and now want a real interface, not curl
  • You want chat history, model switching, and system prompts persisted across sessions
  • You want the same chat available on your phone, your work laptop, your iPad
  • You're considering letting family use the local AI but don't want to teach them an API

What you get

  • Open WebUI running in Docker on your AI host
  • https://ai-rig.tail-abc.ts.net now serves a chat UI instead of (or in addition to) the raw API
  • Multi-conversation history, model picker, system prompt presets — all stored locally on your machine
  • Mobile-friendly: chat from your phone over the tailnet

Prerequisites

  • Local AI gateway (part 1) complete — you have an engine and a working tailscale serve pointing at it
  • Docker installed on the AI host

Mental model

Open WebUI is a client of your engine. It speaks the same OpenAI-compatible API; it just renders the responses as a chat UI. The architecture grows by one box.

Same engine as part 1. New box: Open WebUI. New job for Tailscale Serve: point at port 3000 instead of the engine port. Everything else carries over.

Steps

Five steps. Run the UI container, point it at the engine, re-point Tailscale Serve, claim the admin account, verify from your phone.

Run Open WebUI in Docker ~10 min

Open WebUI runs in a container on the same host as your engine. The trickiest part is letting the container talk to the engine on the host's localhost — different on macOS/Windows vs Linux:

Container-to-host networking, briefly. Part 1 left your engine listening on localhost:11434 (Ollama) or localhost:8080 (llama.cpp). Open WebUI runs in a separate container and can't see the host's localhost directly. The standard fix is the magic hostname host.docker.internal, which resolves inside the container to the Docker host's address.

host.docker.internal resolves automatically; no extra flags needed.

docker run -d \
  -p 3000:8080 \
  -e OPENAI_API_BASE_URL=http://host.docker.internal:11434/v1 \
  -e OPENAI_API_KEY=any-string \
  -v open-webui:/app/backend/data \
  --name open-webui \
  --restart always \
  ghcr.io/open-webui/open-webui:main

Add --add-host host.docker.internal:host-gateway:

docker run -d \
  -p 3000:8080 \
  --add-host host.docker.internal:host-gateway \
  -e OPENAI_API_BASE_URL=http://host.docker.internal:11434/v1 \
  -e OPENAI_API_KEY=any-string \
  -v open-webui:/app/backend/data \
  --name open-webui \
  --restart always \
  ghcr.io/open-webui/open-webui:main

(Replace 11434 with 8080 if you're on llama.cpp.)

Verify the container is talking to the engine:

curl http://localhost:3000/api/config
# Should return JSON about Open WebUI's setup

Re-point Tailscale Serve ~2 min

Part 1's tailscale serve is currently sending traffic to the engine. Now we want the same hostname to land at Open WebUI instead, so users get the chat UI when they visit it.

# Clear the existing serve config (the one pointing at the engine):
sudo tailscale serve reset

# Point it at Open WebUI:
sudo tailscale serve --bg http://localhost:3000

# Confirm what's currently being served:
sudo tailscale serve status

What just changed. The same hostname (https://ai-rig.tail-abc.ts.net) now routes to Open WebUI's port 3000 instead of the engine's 11434/8080. The engine is still running on localhost; nothing tailnet-external can reach it directly anymore — only Open WebUI can, and Open WebUI is the new front door. If you want both URLs (raw API and chat UI), see "Variations" below.

Claim the admin account immediately ~2 min

Open WebUI uses "first user becomes admin" as its bootstrap auth. Get there before anyone else does, even if your tailnet ACLs would block them — admin claim is part of the application setup, not the network.

  1. From your laptop, navigate to https://ai-rig.tail-abc.ts.net.
  2. You'll see a setup screen. Create an account with a real password.
  3. You're now admin. Future signups (if you allow them) will be regular users.

Pick a model and chat ~3 min

In Open WebUI's top bar, pick from the model dropdown — every model you've pulled into Ollama (or every GGUF llama.cpp can serve) shows up. Type something. Wait. Get an answer.

From your phone (also on the tailnet), navigate to the same URL. Sign in with the same admin account. Same models, same conversations.

Tighten ACLs (optional but recommended) ~3 min

If you didn't already in part 1, add a tight ACL so only family can reach the chat UI:

{ "action": "accept", "src": ["group:family"], "dst": ["tag:ai:443"] }

Open WebUI's per-user accounts give you another auth layer; the ACL ensures non-family can't even reach the login screen.

Verify

  • Open WebUI loads at your tailnet URL from your phone
  • The model dropdown lists every model you have available
  • Conversations persist across reloads (stored in the Docker volume)
  • Off-tailnet visitors can't reach the URL

Common issues

  • Open WebUI loads but model picker is empty — the container can't reach the engine. Test from inside: docker exec open-webui curl host.docker.internal:11434/v1/models. If that fails, see step 1's container-to-host networking note.
  • "Server error" when sending a message — engine is overloaded or the model wasn't fully pulled. Check ollama list and the engine's logs.
  • Stuck on signup screen — make sure you're hitting the tailnet URL, not localhost:3000; the latter doesn't have HTTPS and some browsers refuse to send POST to insecure origins.

Variations

  • Keep both URLs (chat AND raw API) — use Tailscale Serve's path mounting: sudo tailscale serve --bg --set-path=/api http://localhost:11434 in addition to the WebUI serve. Now /api/... hits the engine, / hits the UI.
  • RAG over your docs — Open WebUI has built-in RAG: upload files in the UI, it handles chunking and retrieval. See the RAG project for a from-scratch alternative if you want custom logic.
  • Mobile app shortcut — install Open WebUI's PWA (browsers offer "Add to Home Screen") for an app-like experience.
