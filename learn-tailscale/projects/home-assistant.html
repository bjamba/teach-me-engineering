Featured project

🏡 Home Assistant from anywhere

Smart-home control without Nabu Casa, no cloud account, no port forwarding. Tailscale gives you remote access to your local Home Assistant instance.

Featured IoT Intermediate Half-day Prereqs: M3

Why this project

Home Assistant is excellent at running local automations — but reaching it from outside your home historically meant either paying for Nabu Casa, port-forwarding (and exposing the whole admin UI to the internet), or running a public domain with a reverse proxy. Tailscale skips all of this. The HA instance stays local; your phone reaches it over the tailnet whether you're at home, at work, or in another country.

Who this helps

  • You run Home Assistant locally and want remote access without a Nabu Casa subscription
  • You'd rather not poke a hole in your firewall to expose your whole smart home
  • You want push notifications and geofencing from the mobile app working over a private tunnel

What you get

  • HA reachable at https://home-assistant.tail-abc.ts.net from any tailnet device
  • HA Companion mobile app working with full features (notifications, sensors, geofencing)
  • Local voice assistants stay local — no cloud round-trips
  • Tailnet-only access. Your smart home isn't browsable by strangers.

HA controls the smart-home devices on the LAN; you reach HA over the tailnet. Critical detail: ACL grants family → IoT, never IoT → anything else. A compromised doorbell can't pivot.

Prerequisites

  • Home Assistant running somewhere (HA OS, Container, or Core)
  • Tailscale running on the same network or on the HA host
  • HTTPS Certificates enabled in admin → DNS

Steps

Pick your install path ~1 min

Two scenarios depending on how you run HA:

  1. HA OS (the dedicated install) — install the official Tailscale add-on. Easiest path.
  2. HA Container or Core — Docker sidecar pattern, like the Jellyfin project.

Pick one and follow the corresponding step below.

Path 1: HA OS Tailscale add-on ~10 min

  1. In Home Assistant: Settings → Add-ons → Add-on Store.
  2. Search for Tailscale. Install the official add-on.
  3. Start it. Open the add-on's web UI from within HA.
  4. Click "Login" — copy the URL, authenticate in any browser.
  5. The HA host appears in your tailnet.

From any tailnet device, visit http://homeassistant:8123 (or whatever you renamed it).

Path 2: HA Container or Core via sidecar ~15 min

Apply the Docker sidecar recipe:

services:
  ts-ha:
    image: tailscale/tailscale:latest
    hostname: home-assistant
    environment:
      - TS_AUTHKEY=${TS_AUTHKEY?required}
      - TS_EXTRA_ARGS=--advertise-tags=tag:iot
      - TS_SERVE_CONFIG=/config/serve.json
    volumes:
      - ts-state:/var/lib/tailscale
      - ./serve-config.json:/config/serve.json
    cap_add: [net_admin, sys_module]

  homeassistant:
    image: ghcr.io/home-assistant/home-assistant:stable
    network_mode: service:ts-ha
    volumes:
      - ./ha-config:/config
    privileged: true   # needed for some HA integrations

volumes:
  ts-state:

Serve config:

{
  "TCP": { "443": { "HTTPS": true } },
  "Web": {
    "${TS_CERT_DOMAIN}:443": {
      "Handlers": { "/": { "Proxy": "http://127.0.0.1:8123" } }
    }
  }
}

Add the URL to HA's trusted proxies ~5 min

HA refuses connections it thinks are forwarded from an unknown proxy. Edit configuration.yaml:

http:
  use_x_forwarded_for: true
  trusted_proxies:
    - 127.0.0.1
    - ::1

Restart HA. Now requests via Tailscale Serve are accepted.

Use the HA mobile app ~5 min

Install Home Assistant Companion from your phone's app store. When it asks for the server URL, enter your tailnet hostname (https://home-assistant.tail-abc.ts.net).

Log in. Notifications, geofencing, sensor reporting all work — over your tailnet instead of via Nabu Casa.

Lock it down with ACLs ~3 min

Tag the HA host (and any other IoT devices) tag:iot. Add an ACL:

{
  "acls": [
    { "action": "accept", "src": ["group:family"], "dst": ["tag:iot:*"] }
    // no rule with src=tag:iot — IoT devices can't initiate
  ]
}

The IoT-isolation pattern from M5L1. Family controls the smart home; the smart home can't pivot to anything else if a device gets compromised.

Verify

  • HA web UI loads at your tailnet URL from a phone outside your home
  • Companion app connects without errors
  • Off-tailnet visitors can't reach the URL

Common issues

  • "Invalid host header" error — you forgot the trusted_proxies config block.
  • Companion app can't reach — make sure mobile device is on the tailnet and the URL is the full HTTPS tailnet hostname.
  • Bluetooth integrations fail — for HA Container, you need privileged: true and Bluetooth-aware host config.

Caveats

  • Don't Funnel HA. Its admin UI isn't designed for public exposure. Tailnet-only is the right answer.
  • If you really need to grant a third party access (e.g. tech-supporting a friend's HA), invite them as a tailnet user and ACL them in.

Where this leads

  • Pi-hole + tailnet DNS — pair with HA for fully-local DNS-driven automations
  • Use HA's REST API from other tailnet services (Node-RED, n8n, your own scripts) over the tailnet
  • Set up zones, geofences, and presence using the Companion app's tailnet connection
