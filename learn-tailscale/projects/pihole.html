🛡️ Pi-hole + Tailscale DNS

Tailnet-wide ad blocking. Your phone gets blocked DNS even on cellular. Combined with exit nodes, your traffic is ad-free everywhere.

Gallery IoT Intermediate Half-day Prereqs: M3

Why this project

Browser ad blockers only protect browsers. Mobile apps, smart-home telemetry, and shady tracking domains run unfiltered. A network-level DNS sinkhole like Pi-hole catches all of it. The Tailscale twist: by configuring Pi-hole as your tailnet's resolver, every device on your tailnet — even your phone on cellular — uses it.

Who this helps

  • You're tired of trackers and ads inside mobile apps where extensions can't reach
  • You want one ad-blocking config to cover every device on your tailnet
  • You also want to monitor what your IoT devices phone home about

What you get

  • Pi-hole running on a tailnet-connected device with the standard blocklists
  • Every tailnet device (phones included, even on cellular) using Pi-hole for DNS
  • A web UI showing what's being blocked, by which device, in real time
  • The option to add custom rules ("block youtube.com on the kid's phone after 9pm")

Every tailnet device — phone on cellular included — sends DNS to Pi-hole. Match against blocklist → 0.0.0.0 (silently dropped). Otherwise → upstream resolver. Network-level ad blocking, everywhere you go.

Prerequisites

  • A Linux device on your tailnet with Docker (Raspberry Pi 4+ is plenty)
  • Admin access to your tailnet's DNS settings

Steps

Install Pi-hole ~10 min

Easiest: Docker compose:

services:
  pihole:
    image: pihole/pihole:latest
    ports:
      - "53:53/tcp"
      - "53:53/udp"
      - "8080:80/tcp"
    environment:
      TZ: 'America/Los_Angeles'
      WEBPASSWORD: 'set-a-password-here'
    volumes:
      - ./etc-pihole:/etc/pihole
      - ./etc-dnsmasq.d:/etc/dnsmasq.d
    restart: unless-stopped

Verify: curl http://<pi-hole-host>:8080 shows the admin UI.

Make sure the host is on the tailnet ~2 min

Find the Pi's tailnet IP: tailscale ip -4. Save that.

Configure Tailscale to use Pi-hole ~3 min

  1. Admin console → DNS → Nameservers → Custom nameservers → Add.
  2. Enter your Pi-hole's tailnet IP.
  3. Enable "Override local DNS". This forces all tailnet devices to use this resolver.
  4. Save.

Verify ad blocking ~3 min

From any tailnet device:

nslookup doubleclick.net
# Should return 0.0.0.0 (blocked) instead of a real IP

Visit a content site that normally has lots of ads. Most banners are gone.

Phones on cellular ~1 min

Your phone, on cellular, still uses Pi-hole — because the tailnet's DNS configuration applies to every connected device. Ads are blocked on Instagram, YouTube, every app.

Verify

  • nslookup doubleclick.net from any tailnet device returns 0.0.0.0
  • Pi-hole's "Query Log" shows queries from your devices, including your phone
  • Ad-heavy sites/apps are noticeably cleaner

Common issues

  • DNS broken when Pi-hole is down — add a fallback resolver (1.1.1.1) in admin → DNS as a secondary nameserver.
  • Phone's DNS not honoring Pi-hole — some apps use DNS-over-HTTPS to circumvent system DNS. Pi-hole can't catch those.
  • Web UI unreachable — check the host's firewall isn't blocking port 8080 from the tailnet.

Variations

  • AdGuard Home: alternative to Pi-hole, slicker UI, supports DNS-over-HTTPS upstream. Same Tailscale config pattern.
  • Pair with a subnet router: if you want non-tailnet devices on your home network (random visitors, IoT) to use Pi-hole, advertise your home subnet through a subnet router and have your home router's DHCP point at Pi-hole.

Caveats

  • Pi-hole becomes a single point of failure for DNS. The fallback resolver is essential.
  • Don't add yourself to the blocklist by accident — Pi-hole's UI lets you add domains; it's easy to break things.
  • Some apps hardcode 8.8.8.8 or use DNS-over-HTTPS to bypass system DNS. Pi-hole won't catch those.

Where this leads

  • Exit node project — your phone gets ad-blocked DNS even when traveling on hotel wifi
  • Home Assistant — pair for fully-local DNS-driven automations
