🔐 Self-hosted Vaultwarden

Run a Bitwarden-compatible password manager on your tailnet. Use the official Bitwarden mobile/desktop apps and browser extensions — they all point at your private server.

Featured Self-Hosted Intermediate ~1 hr Prereqs: M4

Why this project

Bitwarden is one of the best password managers, and Vaultwarden is the open-source server implementation. The catch with self-hosting historically: a password manager needs to be reachable from every device, with HTTPS, with a stable URL — exactly the things Tailscale solves. The result is an enterprise-grade password manager, fully private to your tailnet, that works on every device you own.

Who this helps

  • You're tired of paying for password manager subscriptions
  • You'd prefer your encrypted vault never live on someone else's server
  • You want the polished Bitwarden mobile/desktop/browser apps without the Bitwarden cloud

What you get

  • Vaultwarden at https://vault.tail-abc.ts.net reachable from any tailnet device
  • Native Bitwarden apps (browser extension, iOS, Android, Mac, Windows, Linux) all pointed at your server
  • End-to-end encryption preserved — Vaultwarden never sees your decrypted passwords
  • Backup discipline that's yours to own

Bitwarden's apps speak the same API to your private server as they would to bitwarden.com. Vaults are E2E-encrypted on each client; Vaultwarden never sees the plaintext. The dashed arrow to backups is your responsibility — vault loss = passwords lost.

Prerequisites

  • Tailscale running on a Linux host (M3)
  • Docker + docker-compose installed
  • The Docker sidecar pattern from the Core project
  • HTTPS Certificates enabled in admin → DNS

Steps

Bring it up via the sidecar pattern ~10 min

services:
  ts-vault:
    image: tailscale/tailscale:latest
    hostname: vault
    environment:
      - TS_AUTHKEY=${TS_AUTHKEY?required}
      - TS_EXTRA_ARGS=--advertise-tags=tag:server
      - TS_SERVE_CONFIG=/config/serve.json
    volumes:
      - ts-state:/var/lib/tailscale
      - ./serve-config.json:/config/serve.json
    cap_add: [net_admin, sys_module]

  vaultwarden:
    image: vaultwarden/server:latest
    network_mode: service:ts-vault
    environment:
      - DOMAIN=https://vault.tail-abc.ts.net
      - SIGNUPS_ALLOWED=true   # turn off after creating accounts
      - WEBSOCKET_ENABLED=true
    volumes:
      - vault-data:/data

volumes:
  ts-state:
  vault-data:
// serve-config.json
{
  "TCP": { "443": { "HTTPS": true } },
  "Web": {
    "${TS_CERT_DOMAIN}:443": {
      "Handlers": { "/": { "Proxy": "http://127.0.0.1:80" } }
    }
  }
}
export TS_AUTHKEY="tskey-..."
docker compose up -d

Create your accounts ~5 min

Visit https://vault.tail-abc.ts.net. Click "Create Account." Create accounts for everyone in your household.

After everyone is signed up, edit the docker-compose to set SIGNUPS_ALLOWED=false and restart. Now nobody else can register, even if they got the URL.

Configure the Bitwarden apps ~5 min per device

Install Bitwarden (not Vaultwarden — they're protocol-compatible) on each device:

  • Browser extension (Chrome / Firefox / Safari)
  • Mobile app (iOS / Android)
  • Desktop app (Mac / Windows / Linux)

On the login screen, tap Settings (gear icon) → Self-hosted. Enter https://vault.tail-abc.ts.net. Save.

Log in normally. The apps connect to your private server.

Tighten the ACLs ~3 min

{ "action": "accept", "src": ["group:family"], "dst": ["tag:server:443"] }

Now only family members on the tailnet can reach Vaultwarden. Even if someone leaked the URL, off-tailnet visitors can't connect.

Set up backups ~10 min

Your password vault is now your responsibility. Back up the vault-data volume regularly:

docker run --rm \
  -v vaultwarden_vault-data:/data:ro \
  -v $(pwd):/backup \
  alpine \
  tar czf /backup/vault-backup-$(date +%Y%m%d).tar.gz -C /data .

Schedule with cron / systemd timer. Store the resulting tarballs somewhere off the home server — encrypted external drive, offsite NAS, B2/S3 with restic.

Verify

  • Bitwarden browser extension can log in and unlock your vault
  • Mobile app sees the same vault
  • The vault syncs across devices in real time
  • Off-tailnet visitors can't reach the URL
  • Backup tarballs are being written and stored offsite

Common issues

  • "Server URL is invalid" — make sure you typed the full https://... URL with no trailing slash.
  • WebSocket errors / sync delays — confirm WEBSOCKET_ENABLED=true and that the proxy passes WebSocket upgrade headers.
  • "Account creation disabled" when expected — restart the container after toggling SIGNUPS_ALLOWED.

Caveats

  • If your home server is offline, you can't add new entries from new devices. Existing devices keep working from cache, but a fresh login fails until the server is reachable.
  • Backups are critical. Losing the data volume = losing your passwords. Test restore at least once.
