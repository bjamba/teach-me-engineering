⭐ Core project · #4

🤖 Local AI gateway

Run large language models on your beefiest machine, hit them from your phone, laptop, or anywhere on your tailnet. Pick your engine (Ollama or llama.cpp), optionally layer LiteLLM in front for per-user keys, routing, and cloud fallback. Private, free, fast — and an excellent reason to upgrade your home GPU.

⭐ Core AI/ML Intermediate Half-day Prereqs: M3 + M4L3 (Serve)

Why this project

Cloud LLM APIs cost money and see your prompts. Local LLMs are free and private — but until now, hard to access from your phone or while traveling. With Tailscale Serve in front, your home AI rig becomes a private API that follows you everywhere.

This is also the gateway project for everything else in the AI/ML topic — RAG over your docs, scheduled summarization tasks, editor integrations all start from "I have a tailnet-reachable LLM."

Who this helps

  • You already use ChatGPT/Claude/Gemini and want a free, private alternative for the 80% of asks that don't need a frontier model
  • You have a beefy machine at home (Apple Silicon Mac, gaming PC, server with a GPU) that's underutilized
  • You'd rather your prompts stayed on hardware you own
  • You want to plug the same private API into editor extensions (Continue, Aider, Cursor) without paying per token

What you get

  • A private API at https://ai-rig.tail-abc.ts.net that responds to OpenAI-compatible requests
  • Your choice of engine: Ollama (easy mode) or llama.cpp (closer to the metal)
  • A polished web UI (Open WebUI) reachable from any tailnet device — your personal ChatGPT alternative
  • Optional LiteLLM layer in front for virtual keys, model routing, and cloud fallback when local is down
  • The ability to swap models or engines freely without contract changes

Prerequisites

  • Tailscale running on the machine that'll host the engine (M3)
  • Tailscale Serve concepts from M4L3
  • Docker installed if you'll use Open WebUI or LiteLLM
  • HTTPS Certificates enabled in admin → DNS

Mental model

Four swappable layers. Once Tailscale Serve is in place at the front, every other piece is replaceable without rewiring the rest.

Two client paths, one engine. The browser path goes through Open WebUI; API-tool clients (Continue, Aider, Cursor — and any other OpenAI-compatible tool) talk to LiteLLM directly. Claude Code itself doesn't go through this — it talks to Anthropic — but tools that compete in its space do.

Engine comparison

All three speak OpenAI-compatible APIs, so the Tailscale Serve / Open WebUI / LiteLLM steps work with any of them.

Hardware notes

  • Minimum: any computer with 16GB RAM can run smaller models (Llama 3.2 3B, Phi-3 Mini). CPU-only is fine, just slow.
  • Comfortable: Apple Silicon Mac with 32GB+ RAM, or a Linux box with an Nvidia GPU (8GB+ VRAM).
  • Excellent: a 4090 or M3 Max. You can run 70B models at usable speeds.

Steps

Pick an engine and install ~5 min

Both engines speak OpenAI-compatible APIs, so the rest of the project (Tailscale Serve, Open WebUI, LiteLLM) is identical. Pick the tab that fits your taste:

Ollama is the friendliest path. Auto-handles model downloads, runs as a service, single command per model. Wraps llama.cpp underneath but hides the complexity.

# Linux:
curl -fsSL https://ollama.com/install.sh | sh

# macOS / Windows: download from ollama.com/download

llama.cpp gives you the underlying engine directly. Better for: custom GGUF model files, specific quantization choices, minimal abstraction, embedded use cases.

# macOS:
brew install llama.cpp

# Linux: build from source or use the prebuilt releases
# https://github.com/ggerganov/llama.cpp/releases

# Verify:
llama-server --help

Get a model ~5–30 min depending on speed

Start with something small to verify everything works:

ollama pull llama3.2:3b

Larger options (download once, run forever):

ollama pull llama3.1:8b           # 4.7 GB · good general model
ollama pull qwen2.5:14b           # 9 GB · stronger reasoning
ollama pull mistral-small:22b     # 13 GB · excellent
ollama pull deepseek-r1:14b       # 9 GB · reasoning

Browse ollama.com/library for more.

llama.cpp uses GGUF files. Download from Hugging Face — search any model name + "GGUF" and you'll find quantized variants:

mkdir -p ~/models && cd ~/models

# Example — download a quantized Llama 3.1 8B (Q4_K_M is a good default):
huggingface-cli download bartowski/Meta-Llama-3.1-8B-Instruct-GGUF \
  Meta-Llama-3.1-8B-Instruct-Q4_K_M.gguf \
  --local-dir .

# Or grab any .gguf via wget / curl from a model card

Quantization choice (Q4_K_M, Q5_K_M, Q8_0, etc.) trades quality for size; Q4_K_M is a sensible default for most home rigs.

Run the server ~3 min

Ollama installs as a service that auto-starts. Test it locally:

ollama run llama3.2:3b
>>> what's the airspeed velocity of an unladen swallow?

Type /bye to exit. Confirms Ollama is working. The OpenAI-compatible HTTP API is now listening on localhost:11434.

Start llama-server with the model file. It exposes an OpenAI-compatible API:

llama-server \
  -m ~/models/Meta-Llama-3.1-8B-Instruct-Q4_K_M.gguf \
  --host 0.0.0.0 \
  --port 8080 \
  -c 4096

Test:

curl http://localhost:8080/v1/chat/completions -H "Content-Type: application/json" -d '{
  "model": "llama-3.1-8b",
  "messages": [{"role":"user","content":"hello"}]
}'

For long-running, wrap it as a systemd service. The default port is 8080 — substitute that everywhere we mention 11434 below.

Expose via Tailscale Serve ~3 min

This step is identical regardless of engine — point Serve at whichever localhost port your engine uses (Ollama: 11434, llama.cpp: 8080):

# Ollama:
sudo tailscale serve --bg http://localhost:11434

# llama.cpp:
sudo tailscale serve --bg http://localhost:8080

Output: https://your-server.tail-abc.ts.net. From any tailnet device, you can now hit the API:

curl https://your-server.tail-abc.ts.net/v1/models

Try it from another device ~3 min

curl https://your-server.tail-abc.ts.net/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "llama3.2:3b",
    "messages": [{"role":"user","content":"Why is the sky blue?"}]
  }'

Wait a few seconds, get a JSON response. That's a private LLM API. Your home rig is doing the inference; your laptop is just sending the prompt.

Add a web UI: Open WebUI ~10 min

Open WebUI is a ChatGPT-style frontend. It speaks OpenAI-compatible APIs, so it works with both Ollama and llama.cpp:

docker run -d \
  -p 3000:8080 \
  -e OPENAI_API_BASE_URL=http://host.docker.internal:11434/v1 \
  -e OPENAI_API_KEY=any-string \
  -v open-webui:/app/backend/data \
  --name open-webui \
  --restart always \
  ghcr.io/open-webui/open-webui:main

(Replace 11434 with 8080 if you're on llama.cpp.)

Now expose Open WebUI on your tailnet:

sudo tailscale serve --bg http://localhost:3000

Visit your tailnet URL in a browser. Create an account (the first user becomes admin), pick your model, chat. From your phone, the same URL works.

Open WebUI's first-user-becomes-admin behavior is the auth: set up the admin account immediately after deploying so a tailnet visitor doesn't claim it.

Soon you'll point Open WebUI at LiteLLM instead (next step). LiteLLM speaks OpenAI-compatible API too, so Open WebUI's connection settings stay the same — just swap the base URL from your engine to LiteLLM's port. Open WebUI's model picker then shows everything LiteLLM exposes, including any cloud fallbacks you configured.

Lock the tailnet down with ACLs ~3 min

Tag the AI host tag:ai. Restrict access to family-only:

{ "action": "accept", "src": ["group:family"], "dst": ["tag:ai:443"] }

Optional: layer LiteLLM in front for keys + routing + fallbacks ~20 min

If you want to share API access with friends, route between multiple models, or fall back to cloud APIs when local is down — LiteLLM is the answer. It's a proxy that speaks OpenAI-compatible API on the front and dispatches to whatever backend you point it at.

Why LiteLLM beats the plain Caddy + shared-secret approach:

  • Per-user virtual keys (each friend gets their own, revocable individually)
  • Per-key rate limits and budgets
  • Model routing: clients ask for "gpt-4", you map it to whatever local model is the equivalent today
  • Cloud fallback: if Ollama is down, LiteLLM transparently falls back to OpenAI / Anthropic
  • Usage tracking and cost calculation across local + cloud

Save as ~/litellm/config.yaml:

model_list:
  - model_name: llama-3.1-8b
    litellm_params:
      model: ollama/llama3.1:8b
      api_base: http://host.docker.internal:11434

  - model_name: smart           # alias — clients ask for "smart"
    litellm_params:
      model: ollama/qwen2.5:14b
      api_base: http://host.docker.internal:11434

  - model_name: smart           # fallback to cloud if local fails
    litellm_params:
      model: claude-3-5-sonnet-20241022
      api_key: os.environ/ANTHROPIC_API_KEY

litellm_settings:
  num_retries: 2
  request_timeout: 60

general_settings:
  master_key: sk-master-key-rotate-this   # for minting virtual keys
  database_url: "sqlite:///litellm.db"

Run it:

docker run -d \
  -p 4000:4000 \
  -v ~/litellm/config.yaml:/app/config.yaml \
  -e ANTHROPIC_API_KEY=sk-ant-... \
  --name litellm \
  --restart always \
  ghcr.io/berriai/litellm:main-stable \
  --config /app/config.yaml

Mint a virtual key for a friend (admin endpoint, requires master_key):

curl -X POST http://localhost:4000/key/generate \
  -H "Authorization: Bearer sk-master-key-rotate-this" \
  -H "Content-Type: application/json" \
  -d '{"models": ["llama-3.1-8b", "smart"], "max_budget": 10}'

# Returns: { "key": "sk-...", ... }

Now swap the Tailscale Serve target from the engine to LiteLLM:

sudo tailscale serve --https=443 off
sudo tailscale serve --bg http://localhost:4000

Friends call your URL with their virtual key:

curl https://your-server.tail-abc.ts.net/v1/chat/completions \
  -H "Authorization: Bearer sk-virtual-key-they-got" \
  -d '{"model":"smart","messages":[{"role":"user","content":"hi"}]}'

If the local engine is offline, LiteLLM transparently falls back to Anthropic. Friends get answers either way; you see the routing in LiteLLM's dashboard.

Re-point Open WebUI at LiteLLM: in Open WebUI's Settings → Connections, add a new OpenAI-compatible connection with base URL http://host.docker.internal:4000/v1 and your virtual key. Open WebUI's model picker now lists every model LiteLLM exposes (local + cloud), with auth and usage tracking enforced by LiteLLM under the hood.

Editor tools (Continue, Aider, Cursor) plug in the same way — point them at https://your-server.tail-abc.ts.net/v1 with a virtual key. Free, private code completion that uses your home rig for the cheap stuff and falls back to a cloud frontier model when needed. Note: Claude Code talks directly to Anthropic and doesn't go through LiteLLM, so this pattern is for Claude-Code-adjacent tools rather than Claude Code itself.

Verify

  • curl /v1/models from a different tailnet device returns your model list
  • Open WebUI works from your phone
  • Generation responses come from your machine (CPU/GPU usage spikes on the host)
  • If you set up LiteLLM: virtual keys work, master key works, off-tailnet calls with no key are rejected

Common issues

  • Open WebUI can't reach the engine — on Linux, host.docker.internal may not resolve; try --network=host or set the engine to bind 0.0.0.0 and point WebUI at the host's tailnet IP.
  • llama.cpp's responses look weird — wrong chat template for that model. Pass --chat-template matching the model family (llama3, qwen, mistral).
  • Slow first response — the model takes time to load into memory. Subsequent calls are fast.
  • Out of memory — the model is too large for your VRAM/RAM. Pull a smaller variant or quantization.
  • LiteLLM fallback not triggering — confirm your master key is correct and the secondary model entry has the right credentials.

Variations

  • vLLM — for production-style serving (continuous batching, multiple concurrent users) on Nvidia GPUs. Different audience than this project, but the Tailscale Serve step is identical: run vLLM (vllm serve meta-llama/Meta-Llama-3.1-8B-Instruct --port 8000), then tailscale serve --bg http://localhost:8000.
  • Caddy + shared API key — minimal-complexity alternative to LiteLLM if all you want is one shared secret. Less flexible but fewer moving parts.
  • Multi-rig setup — run different engines on different home machines (a Mac mini for embeddings, a GPU box for big models), point LiteLLM at all of them, route by model name.
  • Editor integrations — point Continue, Aider, or Cursor at your tailnet URL using your virtual key. Code completion that costs you nothing per token and never leaves your network.

Caveats

  • Local models lag frontier models (GPT-4 / Claude / Gemini) on hard reasoning. The 80/20 case is well-served; the 20% isn't. LiteLLM's cloud fallback handles this gracefully.
  • LiteLLM's master key has full access — rotate it, treat it like a database password, never put it in a public repo.
  • Open WebUI and LiteLLM both have admin UIs. Set strong admin passwords; tailnet-only is good but defense-in-depth matters.

Where this leads

  • RAG pipeline + vector DB — feed your local LLM your own docs, using the same private API
  • Hook your tailnet URL into editor extensions (Continue, Aider, Cursor) for free, private code completion
  • Schedule overnight tasks against your local model — summarize emails, classify newsletters, transcribe meetings
