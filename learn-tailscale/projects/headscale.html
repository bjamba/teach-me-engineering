🏗️ Headscale: self-host the control plane

Run your own coordinator. Same Tailscale clients, your server. Zero dependence on Tailscale Inc.

Gallery Security Advanced Weekend Prereqs: M5 (Ops & security)

Why this project

Tailscale's free tier is generous and the company's reliability is excellent. But for some users, depending on a third-party control plane is a non-starter — research environments with data sovereignty rules, communities that want a fully open-source stack, or operators who've simply outgrown the free tier's 100-device limit. Headscale is an open-source reimplementation of Tailscale's coordination server. The standard Tailscale clients on your devices keep working unchanged; they just point at your server instead of login.tailscale.com.

Who this helps

  • You've grown past the free tier and don't want to pay
  • You have data sovereignty or compliance requirements
  • You're running a self-hosting community and want a fully open stack
  • You enjoy operating things yourself and accept the trade-offs

What you get

  • A Headscale server you control, replacing the Tailscale coordination server
  • The same Tailscale clients on every device, just pointed at your endpoint
  • No device limit (Headscale has no cap)
  • Coordination metadata that lives on your hardware

Headscale replaces only the control plane — coordination, auth, ACL distribution. The Tailscale clients on your devices are unmodified; they just point at your server. WireGuard peer-to-peer underneath stays exactly the same.

Prerequisites

  • An always-on server with a publicly-resolvable hostname
  • Ability to terminate TLS at that hostname (Caddy / Let's Encrypt)
  • Comfort with self-hosting + reading Headscale's docs for breaking changes
  • M5 understanding (you'll write your own ACL policy in HuJSON)

Steps

Provision a server ~10 min

You need an always-on machine with a publicly resolvable hostname (Headscale needs to be reachable for clients to connect). Options:

  • $5/mo VPS (DigitalOcean, Hetzner, Linode) — easiest
  • A home server with a domain pointed at a dynamic DNS provider
  • An existing self-hosting VM

Get a real DNS name and Let's Encrypt cert (e.g. headscale.example.com).

Install Headscale ~30 min

Follow the official install: headscale.net/setup/install. Available as Docker, .deb, .rpm, or source build.

Configure /etc/headscale/config.yaml:

server_url: https://headscale.example.com
listen_addr: 0.0.0.0:8080
private_key_path: /var/lib/headscale/private.key
db_type: sqlite3
db_path: /var/lib/headscale/db.sqlite
acl_policy_path: /etc/headscale/acl.hujson

Run as a systemd service. Reverse-proxy through Caddy for TLS.

Create a user and key ~5 min

headscale users create me
headscale --user me preauthkeys create --reusable --expiration 24h

Point a Tailscale client at Headscale ~3 min

sudo tailscale up \
  --login-server=https://headscale.example.com \
  --auth-key=<preauthkey from headscale>

The device registers against Headscale, joins the tailnet, gets an IP from the configured range, and starts working.

Write your ACLs ~30 min

Headscale supports a HuJSON ACL format very similar to Tailscale's — same groups, tagOwners, acls structure. Save as /etc/headscale/acl.hujson, restart Headscale.

Optional: web admin UI ~30 min

Headscale's CLI is the canonical interface. Third-party web UIs exist:

  • headscale-ui
  • headscale-webui

Maturity varies. Read recent commits and issues before committing to one.

Verify

  • Tailscale clients connect to your Headscale endpoint successfully
  • Devices appear in headscale nodes list
  • Devices on the same Headscale tailnet can ping each other
  • ACL rules deny / allow as expected

Common issues

  • Clients can't connect — reverse proxy / TLS misconfigured. Test the endpoint with curl -v https://headscale.example.com.
  • Device count not what you expected — Headscale users are isolated; check headscale users list and headscale --user X nodes list.
  • Funnel doesn't work — Funnel relies on Tailscale Inc.'s edge infrastructure. Headscale doesn't support Funnel; it's a Tailscale Inc. feature only.

Caveats

  • You give up Funnel entirely
  • You give up the polished admin UI — Headscale is CLI-first
  • Some newer features lag — Tailscale Inc. ships features in their coordinator first
  • You're now responsible for uptime — if your Headscale instance goes down, new device joins fail (existing connections still work)
  • No support contract — community help on GitHub Discussions and Discord; no paid SLA

Where this leads

  • Migrate the rest of your tailnet to Headscale gradually — one device at a time
  • Add a self-hosted DERP relay for full zero-dependency operation
  • Pair with Vaultwarden + Immich for a fully self-sovereign personal stack
