Module 6 · Drill 1 · binary search reps

Binary search variants

Three variants — classic, boundary, and answer-space. Once these three are reflexive you'll see binary search opportunities everywhere.

1 — First and last position of target

2 — Search in rotated sorted array

An ascending sorted array was rotated at some unknown pivot. Find target in O(log n).

3 — Koko eating bananas (answer-space binary search)

There are piles of bananas, and h hours before the guards return. Each hour Koko picks a pile and eats min(k, pile) bananas. Find the minimum eating speed k that lets her finish all piles in h hours.

Solutions

1 — First and last position

def search_range(nums, target):
    def leftmost():
        lo, hi = 0, len(nums)
        while lo < hi:
            mid = (lo + hi) // 2
            if nums[mid] < target: lo = mid + 1
            else: hi = mid
        return lo

    def rightmost():
        lo, hi = 0, len(nums)
        while lo < hi:
            mid = (lo + hi) // 2
            if nums[mid] <= target: lo = mid + 1
            else: hi = mid
        return lo - 1

    if not nums: return [-1, -1]
    l = leftmost()
    if l == len(nums) or nums[l] != target: return [-1, -1]
    return [l, rightmost()]
  
function searchRange(nums, target) {
  function leftmost() {
    let lo = 0, hi = nums.length;
    while (lo < hi) {
      const mid = (lo + hi) >> 1;
      if (nums[mid] < target) lo = mid + 1;
      else hi = mid;
    }
    return lo;
  }
  function rightmost() {
    let lo = 0, hi = nums.length;
    while (lo < hi) {
      const mid = (lo + hi) >> 1;
      if (nums[mid] <= target) lo = mid + 1;
      else hi = mid;
    }
    return lo - 1;
  }
  if (!nums.length) return [-1, -1];
  const l = leftmost();
  if (l === nums.length || nums[l] !== target) return [-1, -1];
  return [l, rightmost()];
}
O(log n) time. Two boundary searches: leftmost where nums[i] >= target, rightmost-1 where nums[i] > target. The lo < hi + hi = mid template is the cleaner-than-most boundary-search recipe.

2 — Search in rotated sorted array

def search_rotated(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if nums[mid] == target: return mid
        # one half is sorted; figure out which
        if nums[lo] <= nums[mid]:    # left half sorted
            if nums[lo] <= target < nums[mid]: hi = mid - 1
            else: lo = mid + 1
        else:                          # right half sorted
            if nums[mid] < target <= nums[hi]: lo = mid + 1
            else: hi = mid - 1
    return -1
  
function searchRotated(nums, target) {
  let lo = 0, hi = nums.length - 1;
  while (lo <= hi) {
    const mid = (lo + hi) >> 1;
    if (nums[mid] === target) return mid;
    if (nums[lo] <= nums[mid]) {
      if (nums[lo] <= target && target < nums[mid]) hi = mid - 1;
      else lo = mid + 1;
    } else {
      if (nums[mid] < target && target <= nums[hi]) lo = mid + 1;
      else hi = mid - 1;
    }
  }
  return -1;
}
O(log n) time. At each step, exactly one half (lo..mid or mid..hi) is sorted ascending. Determine which by comparing endpoints to the midpoint. Once you know the sorted half, decide whether target lies inside it; recurse into that half if so, otherwise the other.

3 — Koko eating bananas (answer-space binary search)

import math

def min_eating_speed(piles, h):
    def can_finish(k):
        return sum(math.ceil(p / k) for p in piles) <= h

    lo, hi = 1, max(piles)
    while lo < hi:
        mid = (lo + hi) // 2
        if can_finish(mid): hi = mid
        else: lo = mid + 1
    return lo
  
function minEatingSpeed(piles, h) {
  function canFinish(k) {
    let hours = 0;
    for (const p of piles) hours += Math.ceil(p / k);
    return hours <= h;
  }
  let lo = 1, hi = Math.max(...piles);
  while (lo < hi) {
    const mid = (lo + hi) >> 1;
    if (canFinish(mid)) hi = mid;
    else lo = mid + 1;
  }
  return lo;
}
O(n log W) time where W = max(piles). Binary search on the answer space [1, max(piles)] for the leftmost k where can_finish(k) is True. The predicate is monotonic: if speed k works, k+1 also works. This is the canonical "answer-space binary search" pattern — interview-defining when you recognize it on a problem that doesn't look sorted at all.
