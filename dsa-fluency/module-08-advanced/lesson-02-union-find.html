Union-Find (DSU) — the connectivity oracle

Union-Find is the data structure for "are these two things in the same group?" It looks like an array of integers but acts like a magic genie answering connectivity questions in nearly O(1). Once you've seen it solve a problem you thought needed BFS, it'll be in your toolkit forever.

The metaphor: the friend-of-a-friend tracker

You're at a party. The host wants to know: are Alice and Eve in the same friend group? Friend group means: "you can chain friendships from one to the other."

Naive approach: BFS the friendship graph. Works, but slow if the host keeps asking different pairs.

Smart approach: every person belongs to a "leader" — someone designated as the representative of their group. Alice points to her leader, who points to their leader, all the way up to a root. Eve does the same. If their roots match, same group. If you decide Alice and Eve should be in the same group, just point one root at the other. Done.

The metaphor

Union-Find is "every person knows their boss; the CEO knows themselves." Two people are in the same company if they share a CEO. Mergers happen by pointing one CEO at the other.

The two operations

OpWhatCost (with optimizations)
find(x)Returns the root of x's group. Used to check whether two elements share a group.α(n) ≈ O(1)
union(a, b)Merge a's and b's groups. Returns False if they were already merged.α(n) ≈ O(1)
α(n) — the inverse Ackermann

The actual mathematical complexity. It grows so slowly that for any n you'd ever encounter (atoms in the universe and beyond), α(n) ≤ 4. So in practice, "α(n)" means "constant — like 1 to 4 operations." Senior interviewers love when candidates can say "with path compression and union-by-rank, find/union is amortized α(n) — basically O(1)."

The full implementation

class DSU:
    def __init__(self, n):
        self.p = list(range(n))   # every node points to itself
        self.r = [0] * n           # rank — approximate tree height

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]   # path compression — flatten on the way
            x = self.p[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb: return False
        # attach smaller-rank tree under larger — keeps tree shallow
        if self.r[ra] < self.r[rb]: ra, rb = rb, ra
        self.p[rb] = ra
        if self.r[ra] == self.r[rb]: self.r[ra] += 1
        return True
class DSU {
  constructor(n) {
    this.p = Array.from({ length: n }, (_, i) => i);   // each node points to itself
    this.r = new Array(n).fill(0);                      // rank — approximate tree height
  }

  find(x) {
    while (this.p[x] !== x) {
      this.p[x] = this.p[this.p[x]];   // path compression
      x = this.p[x];
    }
    return x;
  }

  union(a, b) {
    let ra = this.find(a), rb = this.find(b);
    if (ra === rb) return false;
    // attach smaller-rank tree under larger
    if (this.r[ra] < this.r[rb]) [ra, rb] = [rb, ra];
    this.p[rb] = ra;
    if (this.r[ra] === this.r[rb]) this.r[ra]++;
    return true;
  }
}
class DSU {
  private p: number[];
  private r: number[];

  constructor(n: number) {
    this.p = Array.from({ length: n }, (_, i) => i);
    this.r = new Array(n).fill(0);
  }

  find(x: number): number {
    while (this.p[x] !== x) {
      this.p[x] = this.p[this.p[x]];   // path compression
      x = this.p[x];
    }
    return x;
  }

  union(a: number, b: number): boolean {
    let ra = this.find(a), rb = this.find(b);
    if (ra === rb) return false;
    if (this.r[ra] < this.r[rb]) [ra, rb] = [rb, ra];
    this.p[rb] = ra;
    if (this.r[ra] === this.r[rb]) this.r[ra]++;
    return true;
  }
}

Two optimizations are doing the heavy lifting here:

  1. Path compression — when you walk from a node up to its root, point every node you pass directly at the root. The next find() on any of them is O(1).
  2. Union by rank — when merging, make the shorter tree a child of the taller one. Keeps trees flat.

Without optimizations, a naive DSU degrades to O(n) per op. With both optimizations, it's α(n) ≈ O(1).

The patterns DSU unlocks

ProblemWhy DSU
"Number of connected components"Union every edge. Count distinct roots — that's your answer.
"Detect cycle in undirected graph"For each edge, if its endpoints already share a root, this edge creates a cycle.
"Kruskal's MST"Sort edges by weight; greedily add if endpoints aren't already connected.
"Account merge"Union accounts that share an email. Each final group is one merged account.
"Redundant connection" / find the extra edgeProcess edges in order; the first one that closes a cycle is the answer.
"Friend circles" / "Number of provinces"Adjacency matrix; union i and j wherever matrix[i][j] = 1; count roots.
When DSU beats DFS/BFS

Both DFS and DSU can find connected components. DFS is simpler to write. DSU wins when the graph is given as a stream of edges or queries (online), or when you need to answer many connectivity questions efficiently. If the question is "given these edges arriving over time, when does node X first become connected to node Y?" — that's DSU.

def count_components(n, edges):
    parent = list(range(n))
    rank = [0] * n

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]   # path compression
            x = parent[x]
        return x

    def union(a, b):
        ra, rb = find(a), find(b)
        if ra == rb: return False
        if rank[ra] < rank[rb]: ra, rb = rb, ra
        parent[rb] = ra
        if rank[ra] == rank[rb]: rank[ra] += 1
        return True

    components = n
    for a, b in edges:
        if union(a, b):
            components -= 1
    return components

O(E × α(n)) ≈ O(E) time, O(n) space. The trick that makes counting so cheap: start with n components, and every successful union reduces the count by exactly 1. No need to scan parent arrays at the end.
