LRU cache — the interview classic

"Implement an LRU cache with O(1) get and put" is asked at every FAANG. The point isn't memorizing the answer — it's demonstrating you can compose two data structures (hash map + doubly-linked list) to get behavior neither can give alone.

The metaphor: your fridge

Limited shelf space. You keep what you used most recently up front; old stuff drifts to the back. When the fridge fills up, the back item drops out — it was the one you reached for least recently.

LRU = "Least Recently Used." When something has to be evicted, it's the thing you used longest ago. Least recently — so the one whose last touch is oldest.

The metaphor

An LRU cache is a fridge with a fixed number of shelves and a "front-most is most recent" rule. Every read or write moves the item to the front. When you run out of room, the back falls off.

Watch it work

Capacity = 4. The leftmost item is most recently used; rightmost is the eviction candidate.

The architecture — two structures, one cache

You need both:

  • A hash map from key → cache node. Gives O(1) lookup.
  • A doubly-linked list of cache nodes ordered by recency. Gives O(1) reordering and O(1) tail eviction.

Either alone won't do it:

  • Hash map alone: O(1) lookup, but no notion of "most recent." You'd need to scan to find the LRU — O(n).
  • Linked list alone: O(1) front insert and back evict, but O(n) lookup by key.

Compose them: the hash map stores key → list-node, and the list nodes carry their own (key, value). Now both lookup AND reorder are O(1).

Why the linked list must be doubly-linked

To remove a node from the middle of the list in O(1), you need pointers to both its neighbors. Singly-linked: removing the middle is O(n) because you'd have to walk from the head to find its predecessor. Doubly-linked: the node itself knows its prev and next, so removal is O(1).

The shortcut — Python OrderedDict, JS Map

Both Python's OrderedDict and JS's Map already preserve insertion order and let you reorder cheaply. In an interview, mention you'd use them in production but build the hand-rolled version too — interviewers usually want both.

# Python — production-grade in 8 lines
from collections import OrderedDict

class LRUCache:
    def __init__(self, capacity):
        self.cap = capacity
        self.d = OrderedDict()

    def get(self, k):
        if k not in self.d: return -1
        self.d.move_to_end(k)        # mark most-recent
        return self.d[k]

    def put(self, k, v):
        if k in self.d:
            self.d.move_to_end(k)
        elif len(self.d) >= self.cap:
            self.d.popitem(last=False)   # evict the LRU (front)
        self.d[k] = v
// JS — Map preserves insertion order, so it works the same way
class LRUCache {
  constructor(capacity) {
    this.cap = capacity;
    this.m = new Map();
  }

  get(k) {
    if (!this.m.has(k)) return -1;
    const v = this.m.get(k);
    this.m.delete(k); this.m.set(k, v);   // move to end (most-recent)
    return v;
  }

  put(k, v) {
    if (this.m.has(k)) this.m.delete(k);
    else if (this.m.size >= this.cap) this.m.delete(this.m.keys().next().value);
    this.m.set(k, v);
  }
}
// TypeScript — generic over key/value types
class LRUCache<K, V> {
  private m = new Map<K, V>();
  constructor(private cap: number) {}

  get(k: K): V | -1 {
    if (!this.m.has(k)) return -1 as any;
    const v = this.m.get(k)!;
    this.m.delete(k); this.m.set(k, v);
    return v;
  }

  put(k: K, v: V): void {
    if (this.m.has(k)) this.m.delete(k);
    else if (this.m.size >= this.cap) this.m.delete(this.m.keys().next().value as K);
    this.m.set(k, v);
  }
}

The hand-rolled version — what the interview actually wants

class Node:
    def __init__(self, k=0, v=0):
        self.k, self.v = k, v
        self.prev = self.next = None

class LRUCache:
    def __init__(self, capacity):
        self.cap = capacity
        self.m = {}                  # key → Node
        # sentinel head and tail simplify edge cases
        self.head = Node()
        self.tail = Node()
        self.head.next = self.tail
        self.tail.prev = self.head

    def _remove(self, n):
        n.prev.next = n.next
        n.next.prev = n.prev

    def _add_front(self, n):
        n.next = self.head.next
        n.prev = self.head
        self.head.next.prev = n
        self.head.next = n

    def get(self, k):
        if k not in self.m: return -1
        n = self.m[k]
        self._remove(n)
        self._add_front(n)
        return n.v

    def put(self, k, v):
        if k in self.m:
            self._remove(self.m[k])
        n = Node(k, v)
        self.m[k] = n
        self._add_front(n)
        if len(self.m) > self.cap:
            lru = self.tail.prev
            self._remove(lru)
            del self.m[lru.k]
class Node {
  constructor(k = 0, v = 0) {
    this.k = k; this.v = v;
    this.prev = this.next = null;
  }
}

class LRUCache {
  constructor(capacity) {
    this.cap = capacity;
    this.m = new Map();          // key → Node
    // sentinel head and tail simplify edge cases
    this.head = new Node();
    this.tail = new Node();
    this.head.next = this.tail;
    this.tail.prev = this.head;
  }

  _remove(n) {
    n.prev.next = n.next;
    n.next.prev = n.prev;
  }

  _addFront(n) {
    n.next = this.head.next;
    n.prev = this.head;
    this.head.next.prev = n;
    this.head.next = n;
  }

  get(k) {
    if (!this.m.has(k)) return -1;
    const n = this.m.get(k);
    this._remove(n);
    this._addFront(n);
    return n.v;
  }

  put(k, v) {
    if (this.m.has(k)) this._remove(this.m.get(k));
    const n = new Node(k, v);
    this.m.set(k, n);
    this._addFront(n);
    if (this.m.size > this.cap) {
      const lru = this.tail.prev;
      this._remove(lru);
      this.m.delete(lru.k);
    }
  }
}
class Node<K, V> {
  prev: Node<K, V> | null = null;
  next: Node<K, V> | null = null;
  constructor(public k: K | null = null, public v: V | null = null) {}
}

class LRUCache<K, V> {
  private m = new Map<K, Node<K, V>>();
  private head = new Node<K, V>();
  private tail = new Node<K, V>();

  constructor(private cap: number) {
    this.head.next = this.tail;
    this.tail.prev = this.head;
  }

  private _remove(n: Node<K, V>): void {
    n.prev!.next = n.next;
    n.next!.prev = n.prev;
  }

  private _addFront(n: Node<K, V>): void {
    n.next = this.head.next;
    n.prev = this.head;
    this.head.next!.prev = n;
    this.head.next = n;
  }

  get(k: K): V | -1 {
    if (!this.m.has(k)) return -1 as any;
    const n = this.m.get(k)!;
    this._remove(n);
    this._addFront(n);
    return n.v as V;
  }

  put(k: K, v: V): void {
    if (this.m.has(k)) this._remove(this.m.get(k)!);
    const n = new Node<K, V>(k, v);
    this.m.set(k, n);
    this._addFront(n);
    if (this.m.size > this.cap) {
      const lru = this.tail.prev!;
      this._remove(lru);
      this.m.delete(lru.k as K);
    }
  }
}
Sentinel head/tail trick

Allocating dummy head and tail nodes — neither holds real data — eliminates every "is this node first/last in the list?" branch. The real list is always between them. This kind of trick is what senior interviewers respond to.

Big-O

OpCostWhy
get(k)O(1)Hash map lookup, then O(1) list reorder.
put(k, v)O(1)Hash map insert + list insert + (maybe) list tail removal.
SpaceO(capacity)Bounded by the cache size.

Where LRU shows up in the wild

  • Browser cache — your browser keeps recently visited pages in memory.
  • CDN edge caches — same idea at the network edge.
  • Database buffer pools — Postgres, MySQL, etc. all use LRU-ish replacement.
  • OS page replacement — your computer's RAM uses approximations of LRU to decide which pages to swap out.
  • Memoization with bounded memory — cap your cache to keep memory usage in check.

Both languages have an ordered-by-insertion map that lets us "move to end" in O(1) by deleting and re-inserting. That's the lazy version. The hand-rolled doubly-linked-list version (in the lesson) is what interviewers often ask for explicitly — write that one too if requested. Big-O for both: get O(1), put O(1), space O(capacity).
