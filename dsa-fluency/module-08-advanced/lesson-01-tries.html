Tries — the autocomplete data structure

Hash sets answer "is this exact string in my dictionary?" in O(1). Tries answer "what words start with these letters?" in O(prefix length). When the question is shaped like autocomplete, a hash set falls flat and a trie wins.

The metaphor: a library card catalog

Walk into an old-school library. Card catalog drawers are labeled by letter. Drawer "C" holds every card whose word starts with C. Inside it, sub-dividers labeled "Ca", "Ce", "Ch". Inside "Ca" you find cards for "cat", "car", "case", "castle." When you want to look up "cat", you don't search every card — you walk: C → Ca → Cat. Done.

That's a trie. A tree where each path from the root spells a string. Walking down it is "match these characters one at a time."

The metaphor

A trie is a card catalog. Hash maps store each word as a single key; tries store every shared prefix exactly once. The cost: O(L) per word where L is the word length, regardless of how many words are in the trie.

Visualize it

Watch as we insert "cat", "car", "card", and "dog". Notice the shared prefix "ca-" is stored exactly once — adding "card" only adds one node beyond "car".

The implementation — hash-of-hashes

The simplest representation: each node is a dict mapping a character to a child node. Mark the end-of-word with a special sentinel.

class Trie:
    def __init__(self):
        self.root = {}

    def insert(self, word):
        node = self.root
        for ch in word:
            node = node.setdefault(ch, {})
        node['$'] = True      # sentinel: word ends here

    def search(self, word):
        node = self._walk(word)
        return node is not None and node.get('$', False)

    def starts_with(self, prefix):
        return self._walk(prefix) is not None

    def _walk(self, s):
        node = self.root
        for ch in s:
            if ch not in node: return None
            node = node[ch]
        return node
class Trie {
  constructor() { this.root = {}; }

  insert(word) {
    let n = this.root;
    for (const c of word) { n[c] = n[c] || {}; n = n[c]; }
    n.$ = true;     // sentinel: word ends here
  }

  search(word) {
    const n = this._walk(word);
    return n != null && !!n.$;
  }

  startsWith(prefix) {
    return this._walk(prefix) != null;
  }

  _walk(s) {
    let n = this.root;
    for (const c of s) {
      if (!n[c]) return null;
      n = n[c];
    }
    return n;
  }
}
type TrieNode = { [k: string]: TrieNode | true | undefined };

class Trie {
  private root: TrieNode = {};

  insert(word: string): void {
    let n = this.root;
    for (const c of word) {
      if (!n[c] || n[c] === true) n[c] = {};
      n = n[c] as TrieNode;
    }
    n.$ = true;
  }

  search(word: string): boolean {
    const n = this._walk(word);
    return n !== null && n.$ === true;
  }

  startsWith(prefix: string): boolean {
    return this._walk(prefix) !== null;
  }

  private _walk(s: string): TrieNode | null {
    let n = this.root;
    for (const c of s) {
      const next = n[c];
      if (!next || next === true) return null;
      n = next as TrieNode;
    }
    return n;
  }
}

Big-O — for every operation

OpCostWhy
Insert word of length LO(L)One node created or descended per character.
Search wordO(L)Walk L characters; each step is dict lookup.
Has any word with prefix PO(|P|)Same walk, just doesn't check the terminal flag.
Enumerate all words with prefixO(|P| + total chars in matches)Walk to the prefix, then DFS the subtree.
SpaceO(total chars across all words)Shared prefixes stored once. Worst case O(W × L) for W words.
Why pick a trie over a hash set?

Hash sets give O(1) lookup but cannot answer prefix queries except by scanning every key — O(N × L). Tries give O(L) for both lookup and prefix queries. If the problem mentions "starts with", "autocomplete", "find all words sharing prefix", or word search in a grid where you're DFSing letter-by-letter — that's a trie problem.

The patterns tries unlock

Problem keywordWhy trie
"Autocomplete / search-as-you-type"Walk to prefix, DFS the subtree for completions.
"Word search II" (grid + dictionary)Build trie of dictionary; DFS the grid pruning whenever no trie path exists. Massively cheaper than searching each word independently.
"Replace words" (root → derived word)Insert all roots; for each word, walk until you hit a terminal — that's the shortest matching root.
"Longest common prefix of N strings"Build trie; the deepest node with exactly one child is the LCP terminal.
"XOR maximization" (bit trie)Trie over bits — a special variant that makes maximum-XOR-pair O(n × 32).

class Trie:
    def __init__(self):
        self.root = {}

    def insert(self, word):
        node = self.root
        for ch in word:
            node = node.setdefault(ch, {})
        node['$'] = True

    def search(self, word):
        node = self.root
        for ch in word:
            if ch not in node: return False
            node = node[ch]
        return node.get('$', False)

    def starts_with(self, prefix):
        node = self.root
        for ch in prefix:
            if ch not in node: return False
            node = node[ch]
        return True

def run(ops):
    t = Trie()
    out = []
    for op in ops:
        if op[0] == 'insert': t.insert(op[1])
        elif op[0] == 'search': out.append(t.search(op[1]))
        elif op[0] == 'starts_with': out.append(t.starts_with(op[1]))
    return out

O(L) per insert, search, and starts_with — where L is the length of the word/prefix. Independent of how many words are in the trie. The dict-of-dicts representation is shorter than a class-based one and runs identically. The $ sentinel marks word endings without ambiguity (since '$' isn't a valid character in normal inputs).
