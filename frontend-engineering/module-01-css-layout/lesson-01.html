The Box Model, for Real

Every element on a web page is a box. Once you see the boxes — and the four invisible rules they follow — CSS stops feeling like a guessing game.

⏱ 15 min 🎯 Mental model 🛠 Interactive

The four boxes you keep running into

Every element has four nested boxes: content, padding, border, margin. That's it — every weird sizing bug you've hit comes from confusing them.

What makes this trickier than it should be is a historical decision: by default, width and height only set the content box. If you set width: 300px; padding: 20px; border: 4px solid, the actual element takes up 348px, not 300px. That's the CSS default, box-sizing: content-box, and it's the wrong default for ~everything.

Rule #1 — always reset box-sizing

The first line of any stylesheet you ever write should be:

*, *::before, *::after { box-sizing: border-box; }

This flips the default so that width and height include padding and border. The number you write is the number you see. If you ever import a project that doesn't do this, wonder what the team is doing.

Play with it

Drag the sliders. Toggle box-sizing. Watch the rendered size shift — this is what you need muscle memory for.

Margin is the liar

Padding, border, and content are all predictable — their sizes add up. Margin is the outlier. Margin does weird things, and one of the weirdest is margin collapse.

When two vertical margins meet (a bottom margin on one block element, a top margin on the next), they don't add. They collapse — the larger one wins and the smaller one is discarded.

I have margin-bottom: 40px
I have margin-top: 20px

The gap above is 40px, not 60px. Intuitively wrong, deliberately designed that way so that typographic flow feels natural in prose. But it bites you when you're building layouts.

Rule #2 — stop using margin between layout items

If you're writing a component (cards in a row, list items, buttons), reach for gap via flex or grid on the parent — never margin on the children. Gap doesn't collapse, doesn't leak out of its container, and is trivial to change in one place.

Use margin for typographic flow (spacing between paragraphs, headings, lists — where collapse is actually helpful). Use gap for layout.

Block vs inline — the other split nobody explains

Elements fall into two camps, and CSS treats them totally differently:

  • Block elements (<div>, <p>, <section>, <h1>): stack vertically, fill the available width, honor width and height, honor vertical margin.
  • Inline elements (<span>, <a>, <strong>): flow like text, only take up the space their content needs, ignore width and height, ignore vertical margin.

// block elements stack, fill width:

.block #1 — fills width
.block #2 — fills width

// inline elements flow like text, width: 300px is ignored:

.inline #1 .inline #2 .inline #3 — they just flow like words in a sentence.

If you've ever written width: 200px on an <a> and it didn't do anything — that's why. The fix is usually display: block, display: inline-block, or most commonly in modern layouts, make the parent a flex/grid container and the child participates in that layout system instead.

Rule #3 — the first thing modern CSS did right

The moment you apply display: flex or display: grid to a parent, its children stop following default block/inline flow and become flex items or grid items. They now honor width and height, margins behave predictably, vertical centering just works. Modern layout is a different mode, and most of this lesson's sharp edges disappear inside it.

We'll spend Lessons 2 and 3 in that mode. But you still need the block/inline model for everything that lives outside it — mainly your content/prose.

The big four — remember this

  1. Every element is a box with content, padding, border, margin.
  2. Default box-sizing is wrong. Reset it to border-box, once, globally.
  3. Margin collapses, leaks, and behaves oddly. Use gap for layout; use margin for prose.
  4. Block vs inline dictates how sizing and stacking work — until you enter flex/grid mode, where a sane sizing model takes over.

Self-check

Without running it, predict the total rendered width of:

<div style="width: 300px; padding: 20px; border: 2px solid red; margin: 10px; box-sizing: content-box;"></div>

Answer: the element itself is 344px (300 + 20×2 + 2×2). Margin doesn't count toward the element's width — it pushes it outward. If you got this right and understood why, you're ready for flexbox.
