Responsive Challenge — Container Queries in the Real World

A stat card that adapts not to the viewport but to its own container. Drop the same card into a 240px sidebar, a 400px column, or a 900px main area — and it looks right in all three. One component, three layouts, zero JavaScript.

The old way — and why it's wrong

Before container queries, your "responsive" card looked something like this:

/* make card vertical on mobile, horizontal on desktop */
.card { flex-direction: column; }

@media (min-width: 768px) {
  .card { flex-direction: row; }
}

Seems reasonable. But: what if the card is inside a 300px sidebar on a 1440px desktop? The viewport is wide, but the card's container is narrow. Media queries can't help you — they only know about the viewport.

Container queries fix this. Below, the exact same card markup is rendered in three different container widths. Each instance sizes itself based on how much room it has.

The CSS that makes it work

Three things you need:

  1. A wrapping container with container-type: inline-size — this makes it a "query container"
  2. @container (min-width: ...) rules — like media queries, but scoped to the container's width
  3. Default styles that work for the smallest case (mobile-first thinking)
/* wrapper is the query container */
.slot-body { container-type: inline-size; }

/* default: small layout */
.stat-card {
  display: flex;
  flex-direction: column;
  gap: 0.75rem;
}

/* wide container: horizontal layout */
@container (min-width: 501px) {
  .stat-card {
    flex-direction: row;
    align-items: center;
  }
  .stat-card .sparkline {
    width: 180px;
    height: 60px;
  }
}

/* very narrow: hide the sparkline entirely */
@container (max-width: 260px) {
  .stat-card .sparkline { display: none; }
}

The mental shift

Stop thinking "phone, tablet, desktop." Start thinking "what does this component need to know about itself?" A card needs to know how wide its slot is. Container queries are how you write that.

Your challenge

Open capstone/ in your project (or scratch it out in CodePen for now) and build a container-query-aware KPI card that:

  1. In a narrow container (< 280px): shows label + value only. No icon, no trend arrow.
  2. In a medium container (280–500px): adds the icon on the left and trend below.
  3. In a wide container (> 500px): adds a sparkline on the right and a secondary metric row.

Then drop it inside three different container widths on the same page and verify it looks right in all three. No JavaScript. If you feel tempted to reach for useResizeObserver, that's the old way of thinking.

Browser support note

Container queries ship in all current browsers (2023+). If you need to support Safari 15 or older Firefox, you'll want a polyfill or a fallback. In 2026, this is basically a non-issue.
