Grid Mental Models

CSS Grid is two-dimensional layout: rows and columns working together. Once you stop thinking about it like flexbox, it becomes the most powerful layout tool in CSS.

⏱ 25 min 🎯 2D layout 🛠 Live playground

Grid is a different kind of tool

If flexbox is a single row of items, grid is a page. You define a structure — so many columns, so many rows — and items drop into that structure. Alignments stay consistent across rows because all rows share the same column definitions. That's the superpower.

When to reach for grid

  • Card gallery where every card lines up with its neighbors above and below
  • Dashboard with named regions (header, sidebar, main, footer)
  • Form where labels align in a column and inputs align in the next column
  • Anything where "row AND column alignment" matters

The `fr` unit and the one-liner responsive grid

The single biggest thing grid brought to CSS is the fr unit — a fraction of the available space. No more fighting percentages and margins that don't add up.

grid-template-columns: 1fr 1fr 1fr;     /* three equal columns */
grid-template-columns: 200px 1fr;        /* fixed sidebar + flexible main */
grid-template-columns: 1fr 2fr;          /* two columns, second twice as wide */

Combine fr with minmax(), repeat(), and auto-fit and you get the most famous one-liner in modern CSS:

.grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(250px, 1fr));
  gap: 1rem;
}

That's a card grid that automatically fits as many columns as will fit at 250px minimum, and each column flexes up to fill the remaining space. No media queries. Works on every screen size. You will write this line a hundred times.

Play with it

The playground shows how grid-template-columns actually behaves. Try some values — especially the ones you wouldn't normally think to try.

The difference between auto-fit and auto-fill

Try switching between auto-fit and auto-fill with 3 children in a wide container.

auto-fit: empty tracks collapse, so your 3 items grow to fill the whole row.

auto-fill: empty tracks stay, so your 3 items stick to 120px and the rest of the row is empty "ghost" columns.

For card grids that should always fill the row, auto-fit. For catalog-style layouts that want consistent card widths, auto-fill.

Named grid areas — the killer feature

You can name regions of your grid and assign children to them by name. This reads almost like ASCII art and is the fastest way to build any layout that has named regions.

.app {
  display: grid;
  grid-template-columns: 180px 1fr 220px;
  grid-template-rows: 60px 1fr 50px;
  grid-template-areas:
    "header  header header"
    "sidebar main   panel"
    "footer  footer footer";
  gap: 8px;
}
.app header  { grid-area: header; }
.app aside   { grid-area: sidebar; }
.app main    { grid-area: main; }
.app .panel  { grid-area: panel; }
.app footer  { grid-area: footer; }

That's the "holy grail" layout — the dashboard shell we'll use for your capstone. To make it responsive, swap the grid-template-areas inside a media query. Resize your browser window now — below a certain width, the layout collapses to a single-column stack.

Why this is a big deal

A single grid-template-areas change moves entire sections around. No DOM changes. No JS. No CSS acrobatics. This is what "CSS as a layout language" means.

Placing children explicitly

When you don't want named areas, you can place items by grid line number:

.item {
  grid-column: 1 / 4;   /* from column line 1 to line 4 (spans 3 columns) */
  grid-row: 2 / 3;       /* row 2 only */
}

/* shorthand */
.item { grid-column: span 3; }    /* span 3 columns from wherever it lands */
.item { grid-column: 1 / -1; }   /* full width — line 1 to the last line */

grid-column: 1 / -1 is another line you'll write a lot — "this item spans the entire width of the grid." Great for a header inside an otherwise multi-column layout.

Grid vs flexbox — the decision

Use grid when...Use flex when...
You need 2D alignment (rows AND columns line up) Items flow along one axis
You have a known overall structure (header, sidebar, main) Content dictates the structure (a row of buttons)
You want precise control over where items land You want items to distribute based on content
Building a page or a dashboard Building a component (toolbar, nav, card)

Nest them. A dashboard is a grid. Each card in the dashboard is a flex container. No religion — use the right one at each level.

A checklist before moving on

  • Can you write a responsive card grid without a media query? (repeat(auto-fit, minmax(...))
  • Can you write a dashboard shell with named areas?
  • Do you know when to reach for grid vs flex?

If yes to all three, you're ready for modern CSS. If not, come back to the playground.
