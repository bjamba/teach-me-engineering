Module 2 · Exercise 2

State Refactor — from useEffect soup to clean React

A real-looking "product filter" component that's been written using every anti-pattern at once. Your job is to refactor it. Below is the starting code, the steps to fix it, and the end state. Rewrite it yourself first — don't skip to the solution.

The starting point — all the sins in one file

function ProductList({ initialProducts, currency }) {
  const [products, setProducts] = useState(initialProducts);
  const [search, setSearch] = useState("");
  const [minPrice, setMinPrice] = useState(0);
  const [filtered, setFiltered] = useState([]);
  const [total, setTotal] = useState(0);
  const [priceInUsd, setPriceInUsd] = useState(0);
  const [isReady, setIsReady] = useState(false);

  useEffect(() => {
    setProducts(initialProducts);
  }, [initialProducts]);

  useEffect(() => {
    const result = products
      .filter(p => p.name.toLowerCase().includes(search.toLowerCase()))
      .filter(p => p.price >= minPrice);
    setFiltered(result);
  }, [products, search, minPrice]);

  useEffect(() => {
    const t = filtered.reduce((s, p) => s + p.price, 0);
    setTotal(t);
  }, [filtered]);

  useEffect(() => {
    const inUsd = currency === "USD" ? total : total * 1.1;
    setPriceInUsd(inUsd);
  }, [total, currency]);

  useEffect(() => {
    if (filtered.length > 0) setIsReady(true);
  }, [filtered]);

  const handleSearchChange = (e) => {
    setSearch(e.target.value);
    console.log("User searched");
    window.analytics?.track("search", { term: e.target.value });
  };

  useEffect(() => {
    if (search) {
      console.log("Search active:", search);
    }
  }, [search]);

  return (
    <div>
      <input value={search} onChange={handleSearchChange} />
      <input type="number" value={minPrice} onChange={e => setMinPrice(+e.target.value)} />
      <p>Total: {priceInUsd} USD</p>
      {isReady && <ul>{filtered.map(p => <li key={p.id}>{p.name}</li>)}</ul>}
    </div>
  );
}

What's wrong here (count them)

  1. products is synced from initialProducts in an effect — products shouldn't be state at all if it's just props
  2. filtered is state derived from products, search, minPrice — just compute it
  3. total is derived from filtered — just compute it
  4. priceInUsd is derived from total and currency — just compute it
  5. isReady is state that can never go back to false — also derivable (filtered.length > 0)
  6. Analytics-on-search is duplicated: in the handler AND in an effect. Pick one.
  7. The analytics-in-effect runs on mount even if there was no actual search — events should fire from user actions

The refactor, step by step

1

Delete the sync effect

initialProducts IS the products. We don't need a separate state for it. If the parent passes new products, we want to use them directly.

// gone
const [products, setProducts] = useState(initialProducts);
useEffect(() => { setProducts(initialProducts); }, [initialProducts]);

// use the prop directly
const products = initialProducts;
2

Delete the derive-to-state effects

Every "derived" state + effect pair becomes a single computation during render.

const filtered = products
  .filter(p => p.name.toLowerCase().includes(search.toLowerCase()))
  .filter(p => p.price >= minPrice);

const total = filtered.reduce((s, p) => s + p.price, 0);
const priceInUsd = currency === "USD" ? total : total * 1.1;
const isReady = filtered.length > 0;

No useState, no useEffect. Always correct, one render.

3

Move analytics into the event handler

Logging a search is a thing that happens when the user searches, not a thing that happens "when search state changes". The first framing is accurate and testable; the second is effect-soup.

const handleSearchChange = (e) => {
  setSearch(e.target.value);
  window.analytics?.track("search", { term: e.target.value });
};

Delete the useEffect(() => { ... }, [search]). It never belonged.

4

If filtering gets expensive — THEN use useMemo

Only if you profile and see a bottleneck. Typical lists of hundreds of items are fine to re-filter every render.

const filtered = useMemo(
  () => products
    .filter(p => p.name.toLowerCase().includes(search.toLowerCase()))
    .filter(p => p.price >= minPrice),
  [products, search, minPrice]
);

Don't default to this — but know when to reach for it.

End state — clean version

Before · 7 useStates, 6 useEffects

// ~50 lines of state plumbing
// 5+ extra renders on mount
// analytics fires from two places
// isReady can't go back to false

After · 2 useStates, 0 useEffects

function ProductList({ products, currency }) {
  const [search, setSearch] = useState("");
  const [minPrice, setMinPrice] = useState(0);

  const filtered = products
    .filter(p => p.name.toLowerCase().includes(search.toLowerCase()))
    .filter(p => p.price >= minPrice);

  const total = filtered.reduce((s, p) => s + p.price, 0);
  const priceInUsd = currency === "USD" ? total : total * 1.1;

  const handleSearchChange = (e) => {
    setSearch(e.target.value);
    window.analytics?.track("search", { term: e.target.value });
  };

  return (
    <div>
      <input value={search} onChange={handleSearchChange} />
      <input type="number" value={minPrice} onChange={e => setMinPrice(+e.target.value)} />
      <p>Total: {priceInUsd} USD</p>
      {filtered.length > 0 && <ul>{filtered.map(p => <li key={p.id}>{p.name}</li>)}</ul>}
    </div>
  );
}

Before you say "but TypeScript"

The refactor is the same in TS. The renamed prop (initialProducts → products) is a hint that "initial" is a confused word — either it's a prop you always read (no initial prefix needed) or it's a default for internal state (name it clearly: defaultProducts, and document why internal state is justified).

In this exercise, there's no reason to own a copy of products locally. The refactor is correct.

Your turn

Find a real component in your own code — or a CodeSandbox React tutorial — that has 3+ useEffects. Walk through each effect and ask: "Is this syncing with an external system, or am I deriving/syncing within React?"

For each one that isn't truly external, either delete it (derive inline) or move it to an event handler. Do this on 5–10 components and the pattern becomes reflex. You'll start writing components with fewer effects from scratch.

Checklist — apply to every component you write

  • Can this value be derived? If yes, don't make it state.
  • Is this effect syncing with React itself (state, props, other components)? If yes, it doesn't belong — fix the root cause.
  • Is this handler firing logic that could go in the triggering event? Move it there.
  • Does this setState depend on the prior state? Use the functional form.
  • Am I passing new objects/arrays/functions as props to memoized children? Stabilize or un-memo.
