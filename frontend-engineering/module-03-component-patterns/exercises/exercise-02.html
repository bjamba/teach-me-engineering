Compound Tabs with Keyboard Navigation

You built a basic Tabs in Lesson 2. Now extend it to fully match the WAI-ARIA Tabs pattern — arrow keys to move, Home/End to jump, and automatic vs manual activation. This is how real component libraries implement tabs.

The requirements

1

Roving tabindex

Only the active tab is in the Tab sequence (tabIndex=0). All others have tabIndex=-1. Tab into the tablist moves to the active tab; Tab out moves past all tabs to the panel content.

2

Arrow keys move between tabs

Left/Right arrows on a focused tab move focus to the previous/next tab. Home goes to the first tab, End goes to the last. Arrow keys wrap around the ends.

3

Automatic activation (default)

Moving focus with arrow keys also selects that tab. This is the standard desktop pattern — used by every browser's tab bar.

4

ARIA roles stay correct

role="tablist" on the list, role="tab" on each trigger, role="tabpanel" on each panel. aria-controls on the tab pointing at the panel id. aria-labelledby on the panel pointing at the tab id.

5

Panel focus works

After you Tab past the tablist, you should land on the active panel (if it has focusable content) or on the panel itself (tabIndex=0) so you can scroll/read it with assistive tech.

Keyboard legend

Try the working version first

Click the first tab to focus it, then press the arrow keys. Panel content updates as you move. Tab out — notice focus jumps past the other tabs to the panel.

What changed from Lesson 2

The Lesson 2 version wired context and click handlers — no keyboard nav, no roving tabindex. Here we add three things to Tabs.Trigger and one helper to the context.

// additions to the context
type TabsCtx = {
  value: string;
  setValue: (v: string) => void;
  /* new: list of registered tab values in DOM order */
  register: (v: string) => () => void;
  ordered: string[];
};

Each Trigger registers itself on mount so the context knows the order. Then keyboard navigation is just "find my index, compute the next index, set that value, focus that tab button."

The reference solution

import { createContext, useContext, useState, useEffect, useRef, useId } from "react";

const TabsContext = createContext(null);
function useTabs() {
  const ctx = useContext(TabsContext);
  if (!ctx) throw new Error("Tabs.* must be inside <Tabs>");
  return ctx;
}

export function Tabs({ defaultValue, children }) {
  const [value, setValue] = useState(defaultValue);
  const [ordered, setOrdered] = useState([]);

  const register = (v) => {
    setOrdered((prev) => prev.includes(v) ? prev : [...prev, v]);
    return () => setOrdered((prev) => prev.filter(x => x !== v));
  };

  return (
    <TabsContext.Provider value={{ value, setValue, register, ordered }}>
      <div>{children}</div>
    </TabsContext.Provider>
  );
}

Tabs.List = function List({ children }) {
  return <div role="tablist" className="tabs-list">{children}</div>;
};

Tabs.Trigger = function Trigger({ value, children }) {
  const { value: active, setValue, register, ordered } = useTabs();
  const isActive = active === value;
  const btnRef = useRef(null);

  useEffect(() => register(value), [value]);

  const onKeyDown = (e) => {
    const idx = ordered.indexOf(value);
    if (idx === -1) return;
    let next = null;
    if (e.key === "ArrowRight") next = ordered[(idx + 1) % ordered.length];
    if (e.key === "ArrowLeft") next = ordered[(idx - 1 + ordered.length) % ordered.length];
    if (e.key === "Home") next = ordered[0];
    if (e.key === "End") next = ordered[ordered.length - 1];
    if (next != null) {
      e.preventDefault();
      setValue(next);
      /* focus follows selection (automatic activation) */
      queueMicrotask(() => {
        document.getElementById(`tab-${next}`)?.focus();
      });
    }
  };

  return (
    <button
      ref={btnRef}
      role="tab"
      id={`tab-${value}`}
      aria-selected={isActive}
      aria-controls={`panel-${value}`}
      tabIndex={isActive ? 0 : -1}
      onClick={() => setValue(value)}
      onKeyDown={onKeyDown}
      className="tab-btn"
    >
      {children}
    </button>
  );
};

Tabs.Panel = function Panel({ value, children }) {
  const { value: active } = useTabs();
  if (active !== value) return null;
  return (
    <div
      role="tabpanel"
      id={`panel-${value}`}
      aria-labelledby={`tab-${value}`}
      tabIndex={0}
      className="tab-panel"
    >
      {children}
    </div>
  );
};

Things to notice

  • Register on mount populates ordered in DOM order. The keyboard handler uses this to find the next/previous tab.
  • queueMicrotask moves the .focus() call after React has re-rendered with the new tabIndex. Calling focus() synchronously would try to focus an element that's still tabIndex=-1.
  • We used document.getElementById for brevity — a production version keeps a Map<string, HTMLButtonElement> via refs, so tests don't conflict with real IDs.
  • "Automatic activation" here means selection follows focus. The alternative — "manual activation" — is where arrow keys only move focus, and Space/Enter commits. Prefer automatic for most tabs.

Bonus: manual activation mode

Add an activationMode="automatic" | "manual" prop to Tabs. In manual mode, arrow keys only move focus; Space or Enter commits the selection. This is the right mode when switching tabs is expensive (e.g., each tab loads a different remote dataset).
