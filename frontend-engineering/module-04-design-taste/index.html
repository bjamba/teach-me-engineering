Module 4

Design Taste & UI/UX Patterns

You have instincts and good taste. This module translates those instincts into a vocabulary you can apply every time you build — typography, color, space, rhythm, and the dashboard patterns that actually work.

🔒 Not built yet

This module is stubbed — the outline is set, but the lessons haven't been written. When you're ready to start it, open this folder in a terminal and run /teach-me from Claude Code. I'll build it out based on what you've learned so far and the capstone you're building.

Planned lessons

preview

Typography — the one system that upgrades everything

Modular scale, line-height for body vs headings, font pairing, vertical rhythm, Inter and its friends, when to break the rules.

Color — OKLCH, contrast, semantic palettes

Why OKLCH beats HSL, how to pick a palette in 20 minutes, accent vs semantic colors (success/warn/danger), dark mode implications.

Spacing and rhythm

Why a spacing scale (4/8/12/16/24…) makes everything look better than ad-hoc padding. Using it consistently, and when to break out.

Visual hierarchy without thinking about it

Size, weight, color, position — the four levers. How to direct attention on a dense dashboard. Reading patterns (F and Z).

Micro-interactions — feedback and delight

Hover states that communicate, loading states that don't lie, empty states that help, confirmation that isn't annoying.

Dashboard patterns that work

Linear vs Stripe vs Vercel vs Notion — what they share, what they don't, which pattern fits your capstone.

Planned exercises

Redesign-in-place: take an ugly dashboard to good

Start with a working-but-visually-rough page. Apply typography, color, spacing fixes in passes.

Design system tokens — the capstone's visual language

Define the OKLCH palette, type scale, spacing scale, radii, and shadows for your dashboard. Write them as CSS custom properties in tokens.css.
